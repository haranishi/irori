# 指示書 A1-fix-security：独立のセキュリティレビュー（R-security）の指摘への対応

独立のレビュアーが、あなたの範囲（`packages/{protocol,room,room-client}`・`apps/edge`）に、高1・中2・低を見つけた。全文は `review/security-review.md`（先に読む）。実測つきなので、まず**再現してから**直す（再現できなければ「再現せず」と報告）。触ってよい場所は、あなたの範囲（A1）と同じ。`packages/protocol/src/limits.ts` は私の正本なので、足したい定数は、直接足してよい（足した値と理由を報告に書く）。`docs/` は私が直す。

## 1. 【高】既にある部屋への接続・入退室・ロックを、どの栓も数えない

再現済み：同じIPから、hello のない接続200本がすべて開き、hello→bye の100往復が0.77秒で通る。保存（persist）が往復ごとに2回出る。1台で毎秒約260行の書き込み＝無料プランの1日10万行が数分で尽きる（その日は書き込みが止まる）。

直し方（この形を勧める。変えるなら理由を報告に）：
- **WebSocket の受け付けを、IPごとに数える**（存在確認とは別の枠）：`apps/edge/src/index.ts` の `connect()` で、形の正しいコードの接続も、部屋に渡す**前に** Limiter で数える。既定は毎分60（`WS_CONNECT_PER_IP_PER_MINUTE`。家の8台の再接続の波は通る大きさ）。超えたら 429（`refused`）。試験用の上書きは、既存の仕組み（`ALLOW_TEST_OVERRIDES`）に載せる。運営者が変えられる値にするかは、`MAX_ROOMS_PER_DAY` と同じ扱いでよい。
- **存在しない部屋への WebSocket**は、部屋の Durable Object を起こす前に数える（HTTP の存在確認と順序をそろえる）。
- **IPv6 は /64 に加えて /48 でも数える**（上限は /64 の4倍）。作成の栓（`create`）と WebSocket の栓の両方。
- **部屋ごとの上限**（`packages/room/src/core.ts`）：待ち中（hello 前）の接続は同時に16本まで（超えたら新しいものを即座に閉じる）。新しい席の作成（再開の札での入り直しは除く）は、1分あたり40まで。ロックの切り替えは、1分あたり20まで（超えた分は無視して違反に数える）。これらは `RoomLimits` に足し、試験用に上書きできるようにする。
- **Origin の確認**：`POST /api/rooms` と WebSocket の接続で、`Origin` ヘッダーがあり、リクエストのホストと違うなら 403。`Sec-Fetch-Site` があり `cross-site` なら 403（`POST /api/rooms`）。curl・Node のクライアントは Origin を付けないので通す。
- 試験：実 Worker に当てる試験で、上の各栓が効くこと（200本の hello なし接続が、16本で止まる・61本目の接続要求が 429・100往復の hello→bye が、40回の新席で止まる・ロックを速く切り替えると止まる・別オリジンの POST が 403）。変異を、栓ごとに `tools/mutations/specs/` へ（外すと試験が赤くなること）。

## 2. 【中】書記素の数え方が環境で違い、名前1つでホストが自分の部屋に戻れなくなる

ミャンマー・クメール・ジャワ・バリ文字の結合子音を、Node 24（ICU 77.1）は2書記素、Chromium・WebKit・workerd は1書記素と数える。13個並べた名前で、中継が12個残し、Node 上の RoomSocket（ホスト役）は `joined` を捨て、つなぎ直すと `welcome` まで捨てて進まなかった。

直し方：**受け手の検査は、環境に依らない量（符号位置の数とUTF-8のバイト数）だけにする**。書記素の数えは、送る側（中継の `sanitizeName`）の切り詰めと、画面での表示の切り詰めにだけ使う。
- `packages/protocol`：`name` の検査を、符号位置 ≤ 32 かつ UTF-8 バイト ≤ 96 に（`limits.ts` に `NAME_MAX_CODEPOINTS`・`NAME_MAX_BYTES` を足す）。`sanitizeName`（中継）は、12書記素・32符号位置・96バイトの、どれか先に届いたところで切る（結合記号の積み上げも、この符号位置の上限で抑える）。ゲームの画面の文字（`label`・`title`・`hint`・`body`・選択肢）の検査も、書記素でなく、符号位置の数に替える（上限の数は、いまの書記素の上限と同じ値でよい。日本語は同じ結果になる。例：ボタンの文字12、ヒント40、見出し24、本文120）。
- `room-client`：通らないフレームを黙って捨てる所で、`welcome`・`joined`・`players` のような**名簿を運ぶフレームは、名前の長さだけを理由に捨てない**（構造が正しければ受ける）。
- 試験：上の4つの文字体系の結合子音を13個並べた名前を、Node・実Worker・ブラウザの書記素の数え方の違いをまたいで（`Intl.Segmenter` をまねた偽物で、数え方が違う環境を再現）、中継が切り詰め、ホストの `joined`・`welcome` が受け取られること。結合記号を積んだ名前（約430バイト）が、96バイトで止まること。変異：「受け手が書記素で縛る」に戻す → KILLED。

## 3. 低（あなたの範囲のもの）
- 休止からの復元で、部屋が最大60秒早く閉じる（`core.ts` の最後の操作の時刻を、60秒に1回しか保存しない）。直せるなら、復元のときに照らし合わせる形で（付属情報に載せるなど）。直さないなら、理由を報告に。
- IP のハッシュの塩の置き場（同じ保存領域）は、文書で「仮名化」と書くので、コードは変えなくてよい。
