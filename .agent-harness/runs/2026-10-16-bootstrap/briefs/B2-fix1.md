# 指示書 B2-fix1：スマホの画面の採点（1周目・不合格）への対応

採点：pad-portrait 14／20、pad-landscape 13／20（合格は16以上かつ0点なし）。全文は `review/scoring-pad-portrait.md`・`review/scoring-pad-landscape.md`。**採点には偽陽性がある前提**。直す前に、コードと自分の撮った画面で確かめ、再現できないものは、直さず報告に「再現せず」と書く。見た目の直しは、この指示書のあいだで3周まで。

## 守ること

- 触ってよい場所は、前の指示書（B2）と同じ。加えて、`packages/pad-ui/src/**` とその試験・変異の仕様を、**公開の形（`mountPad` の引数・`look`・`shapeSvg`・送るフレーム）を変えない範囲で**直してよい。`apps/web/src/shared/**` と `apps/web/src/styles/tokens.css` は、B1 の場所なので読むだけ（足したいものは報告）。
- C1 が `tests/e2e/**` で、`data-` 属性を使う横断試験を書いている。**画面の `data-` 属性の名前と値は変えない**。
- 共有部品が入った：`apps/web/src/shared/phrase.ts`（BudouX 方式の文節分け。`phrase(text)`・`softBreaks`。`pad/phrase.ts` は、これを再公開するだけにした）、`tokens.css` の `--line-ui`（操作部品の輪郭。地に4.0:1）。使う。分けた塊の試験（`tests/pad/parts.test.ts`）は私が新しい方式に合わせて直した。
- 容量：`/pad` の JS は gzip で 40,960 B 以下のまま（いまは文節モデルの分が増えて、約36KB。超えるなら報告）。
- 完了は、コマンドの結果と件数で示す。日本語の文書の lint は1件ずつ判断する。

## 必ず直す（効果の大きい順）

1. **語の途中の折り返し**（4人が指摘）。「もう／一度」「本名や／連絡先」「通信の／状態」「待って／います」「決ま／る」など。折り返しうる全文に `phrase()`（pad-ui へ渡す文字列は `softBreaks()`）を使い、ボタン・チップの短い文は `white-space: nowrap`（収まる幅に）にする。縦・横とも、語の途中で折れる所がないことを撮った画面で確かめる。
2. **メニューの入口「…」**。48px以上、画面（縁の内側）の右上に固定（名前の長さで動かない）。案内の文言は「右上の「…」から」にそろえる（19・22）。長押しは、近道として残してよいが、案内には書かない。「退出する」は「一時停止を頼む」と見た目を分ける（取り消せない操作）。
3. **重ねる案内（18〜21）の崩れ**。案内・メニュー・帯を重ねるときは、下の操作部品を隠す（`inert` と暗い不透明の幕）。メニューは札ごと覆う。縦・横とも確かめる。
4. **操作ボタンの色**。色の名前（red・blue・green・yellow・gray）ごとに、テーマになじむ控えめな色に固定する（鮮やかな赤・青・緑・黄を塗らない。席の8色と紛れない）。色なしのボタンは、クリーム地に暗い字で統一。文字（動作の言葉）は必須で、説明の一行も出す。灰色（`gray`）は「押せない」に見せない（押せない状態だけ、薄く・影なし・`aria-disabled`）。撮影の固定データは、同梱ゲームの本物の指定（`games/*/main.js` の `setPad`）に近づける。
5. **傾き（17）**：許可が済むまで、ほかの操作（加速など）は押せない薄さにし、「許可する」を主ボタン（ほかの主ボタンと同じ立体・光）にする。横向きの絵は横持ちにする。
6. **食い違い**：24（外された）は、主ボタンを「コードを入れ直す」（コード入力へ戻る）にし、本文は「もう一度入るときは、大きな画面の人に声をかけてください。」のまま。31（切断が続いた）は、「もう一度試す」を、待ち時間（約20秒）のあいだ押せない見た目にし、「あと◯秒」と減らす。
7. **十字・スティックが小さく、中ほどが空く**（縦）。十字は1マス60〜70px、スティックも大きくし、操作部を上へ伸ばす。説明の一行（11・12・15）は、操作部の近くに置く。早押し（14）は、親指が届く下寄りに。
8. **入力欄の輪郭**（01・02・05・06）：`--line-ui` にして3:1以上。4つの枠の列を、見出し・ボタンの左端にそろえる。「空のままなら…」は、名前の欄のすぐ下・左揃えにし、入力したら消す。注意書きの句点。「コードを変える」を押せる高さ（44px以上）に。
9. **ソフトキーボード**（実機では画面の半分以上を覆う）：入力欄にフォーカスしたとき、入力欄と「部屋をさがす」「参加する」が、見える範囲に残るようにする（`interactive-widget=resizes-content` を `pad.html` の viewport に、`visualViewport` で見える高さを `--vvh` として使う、`scrollIntoView`）。試験：Playwright で、縦は 390×420、横は 844×190 の「キーボードが出た高さ」で、入力欄と主ボタンが見える範囲に入ること。撮影にも、この2場面（縦・横）を足す。
10. **点線の意味を絞る**：点線は誤りと切断だけ。押せない状態は薄く、なぞる範囲（16）は実線。主ボタンの見た目を、17・18も他と同じ（影と光つき）に。形の名前は16px、18の「今すぐつなぎ直す」は48px以上。
11. **言葉**：「ホスト」→「大きな画面」にそろえる（19・24・27）。28 は「ほかの画面」と「大きな画面」が紛れないよう「ほかのスマホやタブ」。07・08 は「つないでいます」（「入っています」と書かない）。27 の「が」の連続を直す。10 は、名前に席の印をつける。
12. 安い低優先：04 に「やめる」。03 の誤り欄の場所を先に空けて、跳ばないように。ロゴの橙と席1の琥珀の見分け（ロゴを少し赤寄りに）。
