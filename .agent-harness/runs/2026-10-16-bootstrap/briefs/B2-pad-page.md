# 指示書 B2：スマホの画面（コントローラーのページ）

あなたは実装担当。設計は固定済みで、この指示書と `docs/` が契約。設計を変えたくなったら、変えずに報告へ書く。前提：A1（`packages/room-client`・`apps/edge`）と A2（`packages/pad-ui`）が作り終えている。ホストの画面（B1）は並行して作られている。

## 作るもの

### 入り方

URLの `#` 以降から、4文字のコードを取る（`normalizeCode`）。無い・正しくないときだけ、4つの枠のコード入力を出す（大文字化・貼り付け対応・自動で次の枠へ）。コードが決まったら `GET /api/rooms/:code`：存在しない→「部屋が見つかりません」とコードの入れ直し、満員・ロック→理由を出す。参加の画面：名前（任意、12文字、前回の名前を `localStorage` から、`placeholder` は空）と、大きな「参加する」。名前の下に、1行の案内「ニックネームで大丈夫です。本名や連絡先は入れないでください」（日英）を必ず出す（子どもが使うため。`docs/legal/data-handling.md` の前提）。このタップを、画面の消灯防止（Wake Lock）の取得と、傾きの許可の準備の起点にする（許可の要求そのものは、`tilt` の画面が出たときの別のボタン）。

### つなぐ

`room-client` で `hello {name, resume}`。`welcome` を受けたら、再開の札を `sessionStorage`（`irori:resume:<code>`）に置く。切れたら自動で入り直す。状態の表示：接続中・再接続中（上に帯）・ホストを待っています（`host:false`）・退出させられた（`kicked`）・部屋が閉じた（`closed`）。それぞれ、次の行動（もう一度入る、コードを入れ直す）のボタンを出す。同じ札で入り直すと、**直前の画面が戻る**（ホストの画面の `pad?` に応えて再送される）。

### 画面の枠

縁に、席の色（`look(id).color`）の太い線と、左上に席の形（`shapeSvg`）と名前。左上の**長押し（600ms）**でメニュー（「ホストのメニューを頼む」＝ `{k:'menu'}` を送る・「退出する」＝ `bye` を送って部屋を出る・「閉じる」）。誤タップを避けるため、短いタップでは開かない。中央に `mountPad`。`PadSpec` の `orient` が `landscape` で縦向きなら、「横向きにしてください」の案内を重ねる（iOSでは向きを固定できないので、案内だけ）。`fx` フレームは `navigator.vibrate` があれば鳴らす。

### スマホで壊れやすいところ（必ず扱う）

引っ張って更新・ダブルタップの拡大・長押しの選択とメニュー・`overscroll`・ノッチの安全領域（`env(safe-area-inset-*)`）・100vh の問題（`100dvh`）・画面の消灯（`wakeLock`。`visibilitychange` で取り直す）・ホームバーの誤タップ・バックグラウンドからの復帰。ボタンは48px以上。文字は16px以上。色だけで区別しない。

### 文言と容量

すべて `t()`（日本語・英語）。スマホやゲームから来た文字列は `textContent` で入れる。JSは gzip で40KB以下（ビルド後に測る）。外部ドメインの読み込み、音声・書体のファイルは入れない。

## 受け入れ条件（あなたがコマンドを実行して確かめる）

1. `npm run typecheck`、`npm test -w @irori/web`、`npm run build -w @irori/web` が通り、件数と容量を報告する。
2. 実Worker（`wrangler dev --local --port 88xx`）に対して、Playwright（Chromium、iPhone 風の390×844・タッチ・モバイルのエミュレーション）で：コードの取り込みと入力、参加、画面の指定（6種すべて）ごとの描画と入力の送信、再接続（接続を強制的に切って、同じ席に戻り、画面が復元されること）、`kicked` `closed` `full` `locked` `no-room` の各表示、左上の長押しのメニュー（短いタップでは開かないこと）、`orient` の案内、を確かめる。ホスト役は、`packages/room-client` を使う簡易のスクリプトでよい（B1の画面とは独立に確かめる）。
3. 画面の確認：390×844（縦）と844×390（横）で、参加・待機・6種の操作画面・再接続の帯・エラー各種のスクリーンショットを `.agent-harness/runs/2026-10-16-bootstrap/review/shots-pad/` に撮る。目視して、はみ出し・文字の重なり・小さすぎる要素・コントラスト不足を点検し、直したことを報告する。
4. 押すタイミングの試験：参加ボタンの連打、画面の差し替えと入力の同時発生（0〜500msで振る）、再接続の直後の入力、を入れる。ページのCPUを10倍遅くした実行（`CDPSession` の `Emulation.setCPUThrottlingRate`）も1本流す。
5. 変異に対する門番の確認：(a) 短いタップでもメニューが開く (b) 再開の札を保存しない (c) `innerHTML` で名前を描く (d) 再接続後に画面を戻さない (e) `kicked` で再接続を続ける、を一時的に入れて、試験が落ちることを確かめ、元に戻す。これらは手作業で終わらせず、`tools/mutations/specs/padpage-*.json` に仕様として残し（形は `tools/mutations/run.mjs` の冒頭）、`node tools/mutations/run.mjs --only padpage-` で全件が KILLED になることを確かめて、件数を報告する。`tools/mutations/` と `tools/tests/` は、`specs/` に自分のJSONを足す以外は触らない。

## 落とし穴（過去の実害）

- 画面がロックされた状態では、Chromiumが起動しないことがある。起動できなければ、止まって報告する。
- iOSのSafariは、画面ロックやタブの切替でWebSocketを黙って切る。再接続は通常の経路。
- 実機でしか分からないこと（振動・傾きの許可・Wake Lockの対応・音）は、確認できなかったと、そのまま書く。「問題ない」とは書かない。
- 待機は、状態の照会で行う。出力の文字列を待つループは書かない。
- 「通った」だけを報告しない。コマンドと出力（件数）を貼る。
