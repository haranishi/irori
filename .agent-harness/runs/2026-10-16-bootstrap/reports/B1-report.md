## 第1版から第3版（要約）

`apps/web/src/host/` は2層に分けた。画面に依存しない規則（`machine.ts`・`roster.ts`・`padplan.ts`・`results.ts`）を、`console.ts` が部屋のつながり・スマホの画面・棚・共有・音・消灯防止とつなぐ。描画は `view-home.ts`・`view-panels.ts`、文言は `messages.ts`（日英）、見た目は `styles/host.css`。docs/ux.md の12か所は実装済み。

- 第2版：文節で折る `shared/phrase.ts` への切り替え、操作部品の輪郭 `--line-ui`（地に4.04:1・カードに3.35:1を `contrast.test.ts` で固定）、canonical から決める公開のアドレス（`origin.ts`）、PUBLIC_URL つきの Worker での撮影
- 第3版：390幅の並び（参加の板→参加者→主役→棚。上の操作群は高さの2割以下）、開発用サーバーの警告、満員の表示、選び方の案内の1か所化、文ごとの折り返し（`ui.ts` の `sentences`）、スマホへ送る文の「です・ます」

決めてほしいことは、第1版から変わらず2つある。

- 途中から来た人は、ゲームの `players` に入れない（始めたときの参加者だけを渡す）。docs/ux.md の8（ゲーム中は待機）を守るためで、指示書の「席の増減は players として渡す」とは、増える側だけ食い違う
- sessionStorage に、鍵のほかに、リーダーの席と、確かめた外部のホスト名（`irori:host:trusted`）を置いた。docs/legal/data-handling.md の表には、まだ無い

### 必ず直す8項目

| # | 直したこと |
|---|---|
| 1 音 | ホームの帯をやめ、見出しの音のボタン1か所で示す。最初の操作の前は「音：クリックで開始」（狭い幅は「音：タップで開始」）で、押すと切り替えずに鳴り始める |
| 2 選び方 | 遊べるときだけ「…［決定］か、キーボードの［Enter］で、このゲームを選びます」。人数が足りないときは「あと◯人そろうと始められます」。狭い幅では、キーボードの部分を出さない |
| 3 階層 | 部屋のコードは人数によらず同じ大きさ（1080pで字の高さ約60px、1366は比例）。題名は68.5px（1080p）。QRは縮めず、板の余白を詰め、光る縁をやめ、QRとコードを板の下に寄せた。見本の絵は16:9の枠で上下の暗い帯を切り、遊べない場合も色つき。参加者2行ぶんの高さを取っておき、主役のカードは0人・1人・4人・8人と警告の状態で同じ高さ（1920で351px、1366で250px。計測） |
| 4 説明 | 主役の説明も文ごとの塊にした。行は文の切れ目で替わり（「光る点を集める。／45秒で…」）、2行まで出る |
| 5 警告 | 板の見出しは「この画面からは参加できません」、コードは小さく淡く。手順①の丸は「!」、②③は淡くして「（開き直したあと）」を添えた。行頭の括弧の空きは詰めた |
| 6 選択中の札 | 輪を札の縁の内側に描き、最初の札は左端を軸に大きくする（左の揃え線から出ない）。札の下から次の見出しまでは約30px。手順の札の下端は、右の板の下端とそろう（1920・1366・1280で計測） |

低優先の7つも入れた。満員の手入力の行は「空いたら、このコードで入れます」。0人のときの「参加を締め切る」は押せない（締め切ったまま0人なら、再開だけ押せる）。結果は表の列を行どうしで共有させ、数字を等幅にした。つながりの覆いの背景を、部屋のない画面と同じにした。メニューの下に「閉じる：スマホの［戻る］か［Esc］」。混雑の文は「…上限に達したので、約2時間後に、自動でもう一度試します」の1文にした。濃い青の星に、明るい縁取りを付けた。

### 再現しなかったもの・直さなかったもの

- 1366の補足の文字：前回もブラウザの計算値は17.1pxで、基準は満たしていた。目で見る字の高さは14px前後になるので、それが指摘の数字と考える。今回は18.05pxに上げ、測って固定した
- 2周の上限で残した：手順①の文が「この画面からは、／スマホは／参加できません」と細かく折れる。混雑の文が「もう／一度」で折れる
- ゲーム中の音の小さな案内は残した。見出しのボタンが隠れているあいだ、音が出ない理由を知る手段がほかに無いため
- 指示書の外で直していない：棚の札の2行目に人数と「あと◯人」が混ざる件、「外す」に警告の印を足す件、閉じた理由を1つに絞る件

## 第5版：C1 が見つけた機能の不具合・確かめの文・遊んだ評価者の指摘

- 途中で空いた席（重い）：参加者を `lineup.ts` で覚え、`left` の席は外す。同じ番号に入った別の人は待機の画面で、入力はゲームへ渡さず、結果にも出ない。ホストがつなぎ直したときは名簿と照らす（同じ名前の別の人だけは見分けられない）。抜けた参加者が結果に載るときは、控えの名前で「退出」になる
- 選択の輪は、棚が部屋より遅く出ると仮に上の帯へ乗る。人が動かす前に棚が出たら、選択中のゲームへ移す。棚が増えたら、主の列を中身で広げず棚の中で横に送る（6本と12本・1920と1366で、見えている部分が板に重ならないことを計測）
- 外部のゲームの確かめに「このゲームには、参加者のニックネームと操作が渡り、ゲームの運営者のサーバーに送られることがあります。」を足した（日英）。確かめを出さない変異2件は KILLED のまま
- 遊んだ評価者の指摘：メニューの開き方の案内は、部屋の最初のゲームだけ・右下の隅・新しい文（右上の「…」）。音の案内は始めの数秒だけ。上の並びから下は棚へ。メニューは「続ける・ホームへ」を上にして一周し、一時停止中のスマホは「メニューを操作中です」。締め切りの文字は QR の幅に合わせた（1920×600 で切れるのを再現）。コントローラーの名前は「スティックか十字キー」。リーダーが自分を外せる件は変えていない
- 狭い幅：選び方の文は主役のカードのすぐ上（下だと、説明が4行のゲームや8人のとき844pxを超える）。道具に短い名前、参加者の札は「切断中」と短く。C1 の既知の不具合1・2・4の試験は、契約の形に書き換えた
- 件数：型の誤り0件、単体189件が通過（うちホスト143件）、ホストの通し22件、C1 の3つ（途中参加・読み上げ・外部のゲーム）を Chromium と WebKit で16件が通過、変異は34件すべて KILLED（空いた席・選択の輪・棚の列・案内・道・一時停止のスマホ・メニューの一周・締め切りの文字の8件を足した）、点検3つは OK
