# B2 報告：スマホの画面（/pad）

第1版で受け入れ条件の5つを満たした。第2版と第3版で、採点の指摘を直した。設計は変えていない。

## 第1版の要点：受け入れ条件の5つは、実 Worker を通した試験で満たした

- QRのURLで開き「参加する」を1回押すと入れる。6種と `remote` の画面を実 Worker を通して描き、入力は正しい席番号でホストに届く。切れたら同じ席へ戻る。画面ロックのあとの死んだ接続には、画面に戻ってから3.8秒で気づいて入り直した
- 作ったもの：`apps/web/src/pad/`（app・play・screens・code-input・long-press・room・wake・phrase・messages・icons）、`styles/pad.css`、`pad.html`、試験 `apps/web/tests/pad/`（単体2本・実ブラウザ11本・土台の `e2e/`）、`playwright.pad.config.ts`、`tools/mutations/specs/padpage-b2.json`
- 契約からのずれ：試験の前処理は `buildWeb()` を先に試し、落ちたときだけスマホの画面だけを組む。Node を使う試験の補助は `.mjs`＋`.d.mts` にした（`tsconfig.json` は触らない）。同じ指定の再送は作り直さず、つなぎ直した直後だけ当て直す。参加のタップでは傾きの許可を求めない
- 実機（iPhone の Safari・Android の Chrome）では、まだ何も動かしていない。振動・傾きの許可・Wake Lock・画面ロックでの切断・キーボードの高さは、差し替えた API と回線の模型で確かめただけ

## 第2版の要点：1周目の採点（縦14点・横13点）を直した（指示書 B2-fix1）

- 直したこと：語の途中の改行（句読点までの節で折る `clauses()`）、右上の56pxの「…」、案内の下で操作を隠す（`visibility:hidden` と `inert`）、色の名前ごとのボタンの色、十字1マス約62px、入力欄の輪郭（地との比3.4〜4.0:1）、ソフトキーボード（`interactive-widget=resizes-content` と `--vvh`）、「大きな画面」への言葉の統一、04 の「やめる」
- 直さなかったこと：10「たろう」に印を付ける件。スマホはほかの人の席を知らず、文はホストの `host.pad.choosing` から届く。代わりに大きな形の下へ「あなたの印」と添えた
- pad-ui は変えていない。変えると `games/*` の SDK の写しが古くなり、`sync-sdk --check` が落ちるため

## 第3版：2周目の採点（縦17点・横16点）に余裕を持たせた（指示書 B2-fix2）

### 結論

指示書の6項目は、口調のうちホストとゲームから届く文を除いて直した。縦横33場面ずつ撮り直し、項目ごとに画像で確かめた。新しい挙動には変異を10件足し、壊すと試験が落ちることを確かめた。

### 項目ごとの対応

| # | 指摘 | したこと | 確かめ方 |

### 直さなかったこと

- 口調：「見てね」「押してね」「入れるよ」「待っていてね」は、ホストの `host.pad.choosingBody`・`remoteHint`・`lateTitle`・`lateBody` から届く。「選ぼう」「連打!」はゲームの文。B1 に「です・ます」への変更を頼みたい（例「大きな画面を見てください」「ゲームを選んで、決定を押してください」）
- 28 の「タブ」：第2版の指示で決めた言葉なので、変えていない（変えるなら「ほかのスマホやブラウザのタブ」）
- 11〜15 の上の空き：操作を親指の届く下にまとめる指示（第2版の7）を優先した
- 16 の中央の目印、20 の回転の絵、14 の回数の表示（大きな画面に出る）は、低い指摘として残した

### 次の担当への注意

- **C1**：外された画面から `data-act="rejoin"` のボタンを外した（指示書の3）。`tests/e2e/console/midgame.spec.ts` の146行目は、外された人に `rejoin` を押させている。この試験は `test.fail` 付きなので、ボタンが無くて落ちても気づけない。`reenter` → コードの入力 → `join` に書き換えが要る
- **C1**：つなぎ直しの案内（`.pp-banner`）は枠の真ん中のカードになり、`data-act="reconnect-now"` は切れた直後から押せる。既存の `data-` の名前と値は変えていない（足したのは `data-named` だけ）
- **B1**：上の口調の4つ。10 の名前に印を付けるなら、文言に形の名前を入れるのが早い（例「橙の丸のたろうが選んでいます」）
- **第4版**（C1 の不具合3）：`pad.html` の viewport から `user-scalable=no` を外した（`maximum-scale` も無し、`interactive-widget=resizes-content` は残す）。部屋の中は `touch-action: none` と touchmove の `preventDefault` の二重で、2本指で同時に操作しても1倍のまま（Chromium は CDP の2本指、WebKit は設定とダブルタップで確認。入る前の画面は広げれば拡大できる）
- **第4版**：C1 の `tests/e2e/console/a11y.spec.ts` の不具合3を契約の形（meta-viewport の違反0件・規則が当たっている・`user-scalable=no` と `maximum-scale` が無い）に書き換え、`KNOWN` を消してスマホの6種にも meta-viewport を当てた。この試験は9件が通過
- **第4版**：単体182件とスマホの通し68件（拡大の試験8件を含む）が通過。変異は拡大の1件を足して43件すべて KILLED（画面全体の `touch-action` を外す変異は、`preventDefault` が守るので効かず、入れていない）
- **第5版**（権利の確認）：メニューのいちばん下（横向きは「閉じる」の右）に控えめなリンク「ライセンスとクレジット」（`data-act="licenses"`、`/licenses.txt` を `target="_blank" rel="noopener noreferrer"` で開く）を足した。menu.e2e に1本（href・新しいタブ・rel・BudouX の帰属表示）、変異に1件（リンクを外す）を足し、変異は44件すべて KILLED（接続の栓を直したあとに流し直した）
