# C1 報告：同梱の4本を、本物どうしで終わり方まで通した。直すべき不具合が4つ残っている

## 結論

- 4本の終わり方9通りを、本物のホスト・本物のスマホ・実 Worker で、結果の画面の中身まで通した。
- `npm run test:e2e` は93件。等速で3回流し、3回とも全件が合格した（落ち・揺れ・飛ばしは0件）。
- e2e の変異10件は、すべて試験が赤くなって KILLED になった（時間切れは0件）。赤くなった試験と理由も1件ずつ見た。
- いちばん重い不具合は、ゲームの途中で空いた席に入った人が、そのゲームの参加者になること（B1 の担当）。
- `test.fail` は1件も残していない。既知の不具合は「いまの振る舞い」を確かめる試験にしたので、直ると赤くなる。

## 実行された試験（〔〕は組。DC・DW・PC・PW は desktop/phone の chromium/webkit）

- tap-race：全員完走→もう一度→再び完走→ホームへ／時間切れ／全員退出〔DC・DW〕
- quiz：全問（正解・誤答・時間切れの点）／全員が時間切れ／全員退出〔DC・DW〕
- dot-grab：倒し続けると動き続ける〔4組〕／時間切れで取った数が結果に／全員退出〔DC・DW〕／席が切れたら止まる／回線が黙って死んでも止まる〔PC・PW〕

## 見つけた不具合（再現の手順つき。どれも直していない）

1. **重い：ゲームの途中で空いた席に入った人が、そのゲームの参加者になる**（B1）。3人で hello-pad を始め、ホストで Esc →「参加者を外す」→ 席2 → 外す → 続ける。外された人が「コードを入れ直す」からコードを打って入ると、席2に入り、待機でなくハローパッドの画面が出る。押した「ぴょん」はゲームに届き、結果にも席2として載る。退出（bye）のあとに別の人が入っても同じだった。見立て：コンソールは参加者を席の番号で覚え（`Running.participants`）、left のあとも外さない。中継は空いた最小の番号を次の人に渡す。docs/sdk.md の「途中参加は次のゲームから」に反する。
2. **ホームの選択の輪が棚に乗らない**（B1）。棚の一覧の読み込みが部屋につながるより遅いと、輪が上の帯のボタン（音）に乗り、リモコンの「右」で棚が動かない。ホストの再読み込みでは、部屋の鍵で先につながるので、遅らせなくても起きた。再現：`/registry/index.json` を1.5秒遅らせて開く。
3. **スマホの画面が拡大を止めている**（B2）。`pad.html` の viewport が `user-scalable=no` で、axe の meta-viewport（WCAG 1.4.4）に当たる。
4. **棚が5本を超えると、右のカードが参加の板（QR）に重なる**（B1）。6本では右端のカードが QR の下半分と部屋のコードに重なる。カードが上に来るときは QR が隠れ、板が上に来るときはマウスで押せない。棚は登録で増える前提なので、本数が増える前に直したい。
5. （直った）傾きの許可を待つ間の薄いボタンが、キーボードでは押せてゲームに届いた。作業の途中で B2 が inert で押せなくしたので、いまは直った形（許可の前は押せない・許可のあとは押せる）を確かめている。

## 気づいたこと（不具合とまでは言えない）

- ゲームの途中でホストを再読み込みすると、ゲームは結果なしで終わり、同じ部屋・同じ席でホームに戻る。設計の文書に書かれていないので、いまの振る舞いを試験で固定した。
- WebKit では、同梱ゲームの枠（空のオリジン）の CSP `connect-src 'self'` が、自分のフォルダのファイルの取得を止めた（axe が CSS を取りに行ったときに見えた）。ゲームが自分の JSON を fetch すると、Safari で失敗するかもしれない。実際のゲームでは確かめていない。
- axe の best-practice の規則（region）は、スマホの画面で出る。WCAG の規則ではないので、違反の数に入れていない。

## 判断と、契約からのずれ

- 同梱ゲームは、apps/web/public の写しでなく、いまの games/・registry/ から配った（`build-registry` の shelfOrder・shipped を読み込んで使う）。写しが古いまま試験が通るのを防ぎ、変異で games/ を壊したときに、その写しを配るため。
- 時間切れは、ホストの時計（ゲームの枠の中も同じ時計）を進めて起こす。まとめて30秒進めると、ping の返事より先に pong の期限が来て、ホストがつながりを捨てる。そこで4秒ずつ進め、返事を待ってから次へ進む。試遊サーバーも同じ。
- 部屋の作成には、試験ごとに別の接続元（CF-Connecting-IP）を名乗らせる。同じ接続元から1時間60回の栓は上書きできず、1回の通しで超えた（B1・B2 と同じやり方）。
- 既知の不具合を `test.fail` にすると、前提の手順が壊れても「予想どおりの失敗」で隠れる。外された画面の「もう一度入る」が消えたとき、実際に隠れた。そこで前提はふつうに確かめ、不具合の箇所だけを「いまの振る舞い」として確かめる（`lib/known.ts`）。

## 未確認のこと

- 実機（iPhone・Android・TV の内蔵ブラウザ）、音、振動、本物の画面ロック。WebKit は macOS の Playwright のもので、iOS の Safari ではない。
- タッチは合成（Chromium は CDP のタッチ、WebKit はマウスの指）。長押しや指のずれは、本物の指と違うことがある。
