# G 報告：同梱ゲーム4本と、登録の道具

担当：`games/` の4本（hello-pad・tap-race・quiz-4・dot-grab）、`registry/` の登録情報とサムネイル、登録の検査・書き出し・撮影の道具。設計は指示書どおりで、変えたくなった点は「ずれと気づき」に書いた。いちばん新しい数は、末尾の「追補3」にある。

## 結論：4本とも end まで動き、変異17件はすべて赤くなった

終わり方は4本で10通りある（追補3で、hello-pad に30秒の時間切れが増えた）。そのすべてを、規則の試験（90件）と C1 の通しの両方で end まで通した。登録の道具は、壊れた登録情報を理由つきで落とし、通れば棚の一覧を書き出す。残る作業は、B1 と C1 の試験の書き換え3件だけだ（追補3の「B1 と C1 へ」）。

## 作ったもの

- **ゲーム4本**：どれも `index.html`・`main.js`（irori とのやり取りと描画）・`logic.js`（画面に触れない規則で、「やること」の配列を返す）・`style.css`・`README.md`・`logic.test.js`。`irori.js`/`irori.d.ts` は `npm run build -w @irori/sdk && npm run sync:sdk` で写す。時刻は、一時停止のあいだ止まる時計で測る。席の色と形は `look(id)` で必ず両方描く。画像と音のファイルはない。
  - hello-pad（1〜8人）：四角をスティックで動かし、「ぴょん」でふくらむ。30秒の時間切れか、リーダーの「おわる」で end。順位は「ぴょん」の回数。
  - tap-race（2〜8人）：「よーい」→ 3・2・1 → `buzzer` 40回で完走。順位は T で決め、締切は 30000ms ちょうどで打ち切る。秒は0.01秒まで出す。
  - quiz-4（1〜8人）：26問から重ならずに8問。前の2回の問題は `storage` で避ける。正解は1000→200点、誤答と時間切れは −200点。DOM で描く。
  - dot-grab（1〜8人）：45秒、点は一度に8個まで。dt で動かし、当たりは移動の線分と光の輪の縁で見る。最後の axis から3秒で止める。
- **登録情報**4件とサムネイル（640×480 の png）。
- **`tools/check-registry.mjs`**：Ajv のスキーマ検査と、id＝ファイル名・二重の id・人数・日付・サムネイルの形式と容量・`entry.bundled`・SDK の写しの一致・ライセンス・URL を見る。**`build-registry.mjs`** は、検査を全部通ったときだけ `apps/web/public/registry/index.json` とサムネイル・ゲームを書き出す。**`make-thumbs.mjs`** は本番と同じ CSP で配り、Chromium で撮る。
- **`tools/tests/registry.test.mjs`**（20件）と、変異 `tools/mutations/specs/games-g.json`（17件）。

## 契約からのずれと、設計への気づき

1・5・8は、もう解決している。

1. check-deps とゲームの試験のぶつかり：別の担当が、試験のファイルを対象から外して解決した。
2. build-registry は、`entry.bundled` が指すフォルダだけを写す（登録していないフォルダを配らない）。`entry.bundled` は `games/<id>/` に限った。
3. 解釈したところ：120KB は 122,880バイト。「未来でない」は UTC+14 の今日まで許す。ライセンスは、よく使う SPDX 41件と LicenseRef-closed（original は素材だけ）。
4. tap-race の得点は 800・600・500・400・300・200・100・50。時間切れでは、完走者の次に、たたいた回数の順で点をつける。
5. dot-grab の停止：スマホが、倒しているあいだ約1秒ごとに同じ値を送り直す形になったので、停止を3秒にした（解決済み）。
6. 文書の食い違い：docs/registry.md はサムネイルを `.webp` と書くが、指示書は `.png`（検査は png・webp・jpg を受ける）。docs/sdk.md のインラインの `<script>` は、`/games/*` の CSP では動かない（hello-pad の README に書いた）。
7. 音は入れていない。コンソールの消音を、ゲームへ伝える仕組みがないため。
8. 作者名：いまは4件とも「irori contributors」。別の担当が変え、共通の決まりとの食い違いは解消した。

## 追補と追補2（遊んだ採点の1周目まで）

- 追補：hello-pad の「おわる」は、リーダーの席にだけ出す。規則でも、リーダー以外の「おわる」は受けない。リーダーが分からないときと、このゲームにいない席のときは、全員に出す。
- 追補2：切断の扱いを4本でそろえた。`online:false` は「いま操作できない」だけで、席が `players` から消えるまで状態を保つ。始めた時点で切れていた席も参加者に入れる。連打は切断で棄権にせず、棄権は席が消えたときだけ（「棄権」0点）、0回は0点。クイズは切れていた問題を0点にし、答えたら「あなたの答え：…」を出す。ハローパッドは四角と名前を床に収め、名前を重ねず、順位の決まりを上の行に出した。

## 追補3：遊んだ採点の2周目への対応（指示書 G-fix-experience2）

**再現**（直す前に、試遊サーバーの8人で。終わってから `POST /stop`）：クイズでは、8人が同じ長い答え（「ニュージーランド」）を選ぶと、答えが3行に折り返して枠からはみ出した（バグ6）。退出した人の札は「切断 0」だった（バグ4）。退出した人は、クイズ・ハローパッド・あつめて点の結果から消えた（バグ3）。ハローパッドは60秒進めても終わらなかった。連打の秒（バグ8）は**再現せず**。試遊サーバーは、スマホの連打を1台ずつ順に送る。3人の完走は 6.8・6.9・7.0秒に分かれ、同じ表示にならなかった。0.1秒の表示で同じになる場面は、規則の試験で示した。あつめて点の当たり（バグ9）は、体と点の距離を試遊サーバーでは狙えない。これも規則の試験で示した（距離40pxは、元の当たり32では取れない）。

**直したこと**（指示書の5つだけ）：
- 抜けた人の結果：4本とも、席が消えた人を、そのときの点のまま結果に載せる。あつめて点では、席が消えた人の体が残っていても点を取らないようにした（抜けたあとに数が増えないため）。全員が抜けたときも、全員を載せて終わる。
- クイズ：席が消えた人の札は「退出」で、点はそのまま見せる（札の文字は規則の `seatTag` で決めて、試験する）。答え合わせの印は答えの下の行に並べた。11文字からは字を小さくして、12文字の答えでも1行に収める。
- 連打：完走の秒を0.01秒まで出す（`toFixed(2)`）。順位は T のまま。
- あつめて点：当たりを、描いている光の輪の縁にした。`DOT_GLOW_R = DOT_R * 2`、`PICK_R = MOVER_R + DOT_GLOW_R`（42）で、描く輪も同じ定数で描く。
- ハローパッド：30秒の時間切れを足した（`GAME_MS`。一時停止で止まる時計で測る）。上の縁に残りの帯、右上に「残り N秒」。「おわる」はリーダーに残した。結果はぴょんの回数で、上の1行・スマホのヒント・README に「30秒」を書いた。サムネイルは OFL の書体で撮り直した（22KB）。

**確かめたこと**：
- `npm run test:games` は90件成功（dot-grab 20・hello-pad 19・quiz-4 26・tap-race 25）。境界も試験した：抜けた人が結果に載る（3本・全員退出の3場面）、光の輪の縁ちょうど（42）は取れて 42.5 は取れない、時間切れの1ms前と締切ちょうど、一時停止中の締切、0.01秒ちがいのゴール。
- 変異を8件足した（指示の3種＝抜けた人を外す［3本］・当たりを32に戻す・時間切れを外す、と、退出の札・抜けたあとの取得・0.1秒表示）。`node tools/mutations/run.mjs --only games-` は**17件中17件 KILLED**。直後の `npm run test:games` も90件成功。
- `node tools/sync-sdk.mjs --check` は OK（4本）、`check-registry` は OK（4件）、`build-registry` は4件。ゲームの JS は厳しめの tsc で誤り0。
- 答え合わせの絵：仮想プレイヤー8人（本番と同じ CSP）で、同じいちばん長い答えを選ばせ、1280×720 と 1920×1080 で撮って Read で見た。8文字と12文字に差し替えても、文字と印は枠の中に収まり、重ならず、切れなかった（4枚とも数で測った）。
- C1 の試験（指示のコマンド、desktop-chromium の6本）：20件成功、2件失敗。失敗は midgame の2件だけで、どちらも hello-pad の結果に、外された席2の行が増えたためだ（直した挙動どおり）。続けて timing を phone-chromium で流し、hello-pad で入り直しを繰り返す2件も成功した（30秒より前に終わる）。
- 本物のコンソールでの確認（試遊サーバーの8人、再現と同じ手順。終わってから `POST /stop`）：答え合わせの印は、7文字と8文字の答えの下の行に収まった（撮った絵を Read で見た）。退出した人の札は「-200 退出」。退出した人は、クイズ・ハローパッド（ぴょん3回）・あつめて点の結果に残った。ハローパッドは29秒で「残り 1秒」、30.5秒で結果になった。連打の秒は 6.80・6.92・7.04秒。

**C1 の試験の期待を書き換えたもの**（直した挙動の分だけ）：tap-race の秒の形を `\d{2}` に。quiz・hello-pad・dot-grab の全員退出は「結果は空」から、3人とも抜けたときの点で「退出」の印つきに（quiz は札の「退出」、dot-grab は取った数も確かめる）。hello-pad には時間切れの1件を足した。

**B1 と C1 へ**：midgame.spec.ts の142行と166行は「外した席は結果に出ない」前提なので、B1 の書き換えが要る。いまは席2が、外されたときの回数（ぴょん1回・0回）で「退出」の印つきの行になる。166行の行は、空いた席に入った別の人ではなく、外された元の人（控えの名前）だ。C1 の playtest.spec.ts の110行（`/^\d+\.\d秒$/`）も、0.01秒の表示で落ちる（流して確かめた。受け取った文字は「2.69秒」）。もう1つ、hello-pad を長い試験の台に使うと、30秒で終わる。

**気づき（変えていない）**：クイズは減点があるので、途中で抜けた人が、残って時間切れを重ねた人より上の順位になることがある。試遊サーバーでは、2問目の出題中に抜けた p8（-200）が、残った7人（-1600）を抑えて1位になった。「点はそのまま」の指示どおりにした。順位の付け方は変えていない。

**直さなかったこと（記録だけ）**：始める前から切れていた人が走者に入る件、ホストの読み込み直しでゲームが消える件、バグ5・7・10。登録情報の hello-pad の紹介文には、30秒を書いていない（指示の範囲外）。
