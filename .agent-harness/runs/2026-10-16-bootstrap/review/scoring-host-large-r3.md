# 画面の採点 host-large-r3（ホスト画面・1920×1080と1366×768・28枚）

**合計15点／20点（0点の項目なし）。合格ライン16点に1点足りない。**
崩れた画面はない。両幅とも収まりは良い。点を落とした理由は大きく2つで、ホームでQRと主役カードが視線を取り合うことと、いま起きている状態と画面の案内文が食い違う箇所が残っていること。

## 問題の一覧（中5件・低19件。高はなし）

### 中
1. 音の表示が食い違う（01〜03・13・14、両幅）。上部の帯は「音を出すには、この画面をクリックするか、キーを押してください」と言い、見出しのボタンは「音：オン」と言う。→ 帯が出ている間は、ボタンを「音：クリックで開始」にして帯と同じ状態を示す。
2. 遊べないゲームに「選びます」と案内している（02、両幅）。選択中の「連打レース」は「あと1人で遊べます」なのに、下の行は「［決定］か［Enter］で、このゲームを選びます」。→ 人数が足りないときは「あと1人そろうと始められます」に差し替える。
3. QRとコードが主役カードより強い（01〜03・13、両幅）。白いQRが画面でいちばん明るく、コードがいちばん大きな文字。QRは右の列の上半分にあり、決まりの「右下」より上に出ている。→ QRは3m先から読む大きさが要るので縮めない。代わりにコードを60px前後に固定し、主役の題名を大きく（約72px）、プレビューを明るくする。
4. 主役の説明が句の途中で折れる（01・14、両幅）。「光る点を／集める。」となり、カードの右には約240pxの空きが残る。13では同じ文が1行に収まっている。→ 読点の後で折れるようにするか、1行に収まる幅を取る。
5. 開発用サーバーの警告と案内が食い違う（14、両幅）。枠の見出しは「スマホで参加／アプリもアカウントも要りません」のまま。使えない部屋のコード（QNGH・22P8）が枠でいちばん大きい。手順1は警告文なのに、ふつうの手順と同じ橙の丸。手順2・3も、できる手順のように残る。→ 見出しを「この画面からは参加できません」に替え、コードは小さく淡く、手順1の丸は「!」に、手順2・3は淡くする。

### 低
6. 満員でも「irori.example/pad で、このコードを入力」がそのまま出る（13、両幅）。→「空いたら、このコードで入れます」に言い換える。
7. 選択中カードの拡大と輪が、左の揃え線から約14px（1920）・約11px（1366）はみ出す（01・13・14）。→ 棚の左に拡大分の余白を取る。
8. 選択中カードの輪と「はじめかた」の見出しの間が約13〜18px（01・14）。主役カードと「ゲーム」の見出しの間（約30px）と比べて詰まる。→ 30px前後にそろえる。
9. 右の枠と手順カードの下端が、約30px（1920）・約22px（1366）ずれる（01）。→ 下端をそろえる。
10. 部屋のコードの大きさが場面ごとに変わる（01で文字の高さ約85px、02・03で約60px。1366では約55px→約42px）。主役カードも13だけ小さい（プレビュー幅 約440px→約350px）。→ 大きさを固定し、足りない高さは余白で吸収する。
11. 棚のカードの2行目が、人数（「1〜8人」）と状態（「あと1人で遊べます」）の2つの意味で混ざる（02・03）。→ 2行目は人数にそろえ、遊べないカードには鍵などの印を付ける。
12. ボタンの形が2種類ある。見出しとダイアログのボタンは丸く、共有の3ボタン（08）とメニュー行（06）は角の小さい四角。→ 操作ボタンは丸にそろえる。
13. 選択中の表示が2通りある。04・05・06・07は塗り＋輪、08の「Xに投稿」は輪だけ。→ 1通りにそろえる。
14. エラーの背景が2通りある。09〜11はほぼ黒、12はぼかしたホーム（撮影の疑いあり）。→ どちらかにそろえる。
15. さくら（濃い青の星と縁）は、暗い地との差が推定約3:1で、基準ぎりぎり（13、両幅）。名前の文字があるので見分けはつく。→ チップの地を少し明るくするか、星に明るい縁取りを付ける。
16. 1366では補足の文字が14〜16pxになる。該当は「記録」（07）、「つながっていません」（03）、共有の注記（08）、「家のWi-Fiの中でも動かせます。」（10）、「部屋のコード」（01）。→ 最小17px（1080pの24px相当）にする。
17. プレビュー画像の上下に暗い帯があり、枠の中にもう1つ枠があるように見える（05、03の主役）。→ 画像を枠いっぱいに広げる。
18. 結果の数字の幅がそろわず、「記録」の位置が行ごとに数pxずれる（07）。→ 数字を等幅の書体にする。1位の祝い方も静止画では控えめ（動きは未確認）。
19. 「今日作れる部屋の数が、上限に達しました」と「約2時間後に、自動でもう一度試します」がどうつながるのか読み取りにくい（10）。上限中に「いますぐ試す」を押しても失敗しやすい。→「約2時間後に空きが出ます」のように、理由と時間を1文でつなぐ。
20. 参加者0人でも、見出しに「参加を締め切る」が出ている（01）。→ 0人のときは押せない表示にするか、隠す。
21. 「外す」が枠線だけのボタンで、取り消せない操作だと見た目から分からない（04）。既定のフォーカスが「やめる」なのは良い。→ 小さな警告の印を添える。
22. 一時停止メニューに閉じ方の案内がない（06）。05には「もどる：スマホの［戻る］か［Esc］」がある。→ 下に1行添える。
23. 手順1の「（右の警告）」は、全角括弧の空きで行頭が右に寄って見える（14。1366で目立つ）。→ 行頭の括弧の空きを詰める。
24. 部屋を閉じた理由が「操作がなかった」か「時間が終わった」かの二択のまま（11）。→ どちらか分かるなら、そちらだけ書く。

## 撮影の疑い
- ホームの上部の音の帯：撮影中に一度も操作していないために出ている可能性がある。04の背景では消えている。ただ、帯が出ている間は問題1の食い違いが起きる。
- 13の「さくら」のチップだけ縁が二重に見える：撮影時のフォーカスが残った可能性がある。
- 02で「連打レース」が選ばれているのは、撮影のために選択を動かしたためと思われる（01の既定は「あつめて点」）。この状態になれば、問題2の食い違いは実際に起きる。
- エラーの背景の違い（問題14）は、エラーを起こした手順（新しく開いた画面か、部屋がある画面か）の違いによる可能性がある。
- 住所の「irori.example」、結果の「記録 0.9秒」（40回の連打）は試験用のデータとみなし、採点の対象にしていない。
