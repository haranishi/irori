# S-ui 採点（担当 host-large-r5）

## 結論：17／20点で合格。高はなく、重いのは3点

合計は17点で、合格の条件（16点以上かつ0点なし）を満たす。減点は「余白と整列」「タイポグラフィ」「アクセシビリティ」の3項目で、各1点。どちらの幅にも、表示の崩れはない。最も重い問題は次の3つ。

1. 手順番号の文字の比が足りない（01・14）。白字×明るい橙で約2.3〜2.5:1となり、大きい文字の基準3:1に届かない。
2. ホームの右パネルで、見出しとQRの間が1080で約160〜290px空く（01〜03・13・14）。見出しだけが浮いて、読み込み待ちのように見える。
3. 不自然な折り返しが2画面にある。10の「自動でもう／一度試します」と、14の手順1で「スマホは」だけになる行。

見方：画像だけを見て、28枚（1920x1080と1366x768で各14枚）を1回ずつ開いた。前の採点・コード・設計文書は見ていない。比はすべて画面の色からの目測で、±0.5程度の誤差を含む。「両幅」は2つの幅の両方で起きていることを指す。

## 問題の一覧：高はなく、中が5件・低が14件

01〜14は画像の番号で、2つの幅で共通。

### 中
1. 手順番号の比（01・14、両幅）。白字×明るい橙で約2.3〜2.5:1。→ 14の「！」の丸と同じ「クリームの地に濃い字」にする。橙の地のままなら、字を濃い焦げ茶（#2A1A10程度）にすれば約7:1になる。
2. 右パネルの空白（01〜03・13・14、両幅）。→ 見出しをQRの直上（間隔40px程度）まで下げて1つの塊にし、上に空く場所に参加手順の短い版（「カメラでQRを読む→『参加する』を押す」）を置く。最初の1人が入ると左の「はじめかた」は消える（02）ので、後から来た人の助けにもなる。
3. 「もう／一度」の折り返し（10、両幅）。→ 「…上限に達しました。」と「約24時間後に、自動でもう一度試します。」の2文に分け、文の切れ目で改行する。
4. 手順1が4行に折れる（14、両幅）。「この画面からは、／スマホは／参加できません／（右の警告）」と、「スマホは」だけの行ができる。→ 「この画面では参加できません（右を参照）」程度に縮め、2行以内に収める。
5. 詳細の縮小画像の上下に黒い帯（05、両幅。1080で上約55px・下約60px）。ゲームを始める前に毎回通る画面なので目に付く。→ 枠の縦横比を画像に合わせるか、画像を枠いっぱいに表示する。

### 低
6. 棚の縮小画像は下半分以上が暗く覆われ、4枚を絵で見分けにくい（01〜03・13・14）。→ 暗い重ねを文字の下の1/3だけにする。
7. 「さくら」の札だけ枠が二重で地も明るく、選ばれているように見える（13、両幅）。→ 明るい縁は星の印だけに付け、札の枠はほかと同じ1本にする。
8. 10の本文だけが白い太字で、文末の句点もない。09・11・12は灰色の普通の太さ。→ ほかのエラー画面と同じ書式にする。
9. 14の「npm run dev が表示する『大画面で開くURL』」は開発者向けの言葉。→ 本文は一般の人向けの言い方にし、コマンド名は小さい補足の1行に回す。
10. 14では同じ警告が3か所（右の見出し・警告の枠・手順1）に出ていて、主役の「あと1人で遊べます」とも食い違う。→ 手順1を短くし、主役の案内は消すか「開き直すと遊べます」に替える。
11. 02で、主役の「あと1人で遊べます」と棚の下の「あと1人そろうと始められます」が同じことを言っている。→ どちらか一方にする。
12. 主役の題字の縦位置が、状態によって約30pxずれる（02はy≈205、03はy≈235）。→ 中身を上端そろえで固定する。
13. 0人のときの「参加を締め切る」（01・14）は点線の枠だけで、文字は明るいまま。押せないことが分かりにくい。→ 文字と印も暗くする。
14. 棚の右端（1080で約1160px）が、主役カードと手順の右端（約1385px）とそろわない。ゲームが増える前提なら許容できる。
15. 05は右の列のメタ情報の下が約150px空き、04はボタンの右に約400pxの空きがある。
16. 07の1位の強調が、枠と色だけで控えめ。→ 1位の行の文字を一回り大きくする。王冠はリーダーの印と紛れるので避ける。
17. 1366の小さい文字（07の「記録」、05の操作とメタ情報）は約15〜16px。1080に換算すると約21〜22pxで、目安の24pxを少し下回る。
18. 03の切断中の「けんた」のひし形はくすんだオリーブ色で、地との比はおよそ3:1前後。文字が添えてあるので実害は小さい。
19. 11の「しばらく操作がなかったか、部屋を使える時間が終わりました」は文の筋が取りにくい。→ 「操作がしばらくなかったため、または使える時間が過ぎたため、部屋を閉じました。」

## 撮影の疑いと未確認：仮データと仮ドメインは減点していない

- 07の「記録 0.9秒」で40回たたくのは不可能で、撮影用の仮データとみられる（撮影の疑い）。
- 01・08の「irori.example」は試験用の仮ドメインとみられる（撮影の疑い）。公開時に本物のドメインへ替わるかは要確認。
- 08だけ、背景がぼかした画面ではなく黒一色。開いた元の画面の違いか、背景を描く前に撮った可能性がある（撮影の疑い）。
- 13の「さくら」の二重の枠は、フォーカスやホバーの状態を撮った可能性もある。両幅で同じだったので、意図した表示として採点した。
- 部屋コードは画像ごとに違う（55TD・G457・YV4S・XLNB・8LQ4・YNB3）。撮影ごとに部屋を作り直したためとみられ、問題ではない。
- 未確認：音（見出しの「音：クリックで開始」）、09の再接続中の動き（残り時間や回る印が出るか）、06の「ホームへ」で確認が出るか、選択の輪と光の動き。

## メインループの裁定（2026-10-16）

- **重い問題1（手順番号の比が2.3〜2.5:1）は偽陽性。** `.guide__num` の文字は `--ink`（#1a1411）、丸は `--ember`（#ff8a3d）で、計算した比は 7.77:1。01の丸を切り出して4倍に拡大し、数字が暗い色であることを確かめた。2.35:1 は「白い数字」で計算した値と一致するので、評価者は数字を白と見誤った。
- 問題2（右パネルの見出しとQRの間の空き）・問題3（2画面の折り返し）・詳細の黒い帯は、見た目の調整を2周で止めたときの残り。直さず、人に返す。
- 合計17/20は、4周目と同点で、合格線（16点以上かつ0点なし）を満たす。差し戻しの上限は使い切っているので、これ以上は回さない。
