# 画面の採点（ホストの大画面・host-large）

- **合計14点／20点で不合格**（合格は16点以上かつ0点なし。0点の項目はない）
- 対象：1920×1080 と 1366×768 の各12枚、計24枚。各画像を1回ずつ開き、開き直していない
- 手順の注記：画像のファイル名を知るために、2つの画像フォルダの一覧を1回だけ表示した（読み取り機能ではフォルダの中身を一覧できなかったため）。コードと文書は、指示書のほかは見ていない

### 端末への適合（幅ごと）
- 1920×1080：2点。12枚とも収まる。上部の操作欄（音 オン・ロック・共有）のボタンは高さ約64pxで押しやすい
- 1366×768：2点。12枚とも収まる。文字も同じ比率で小さくなり、補足の文字は約14〜16px（問題10・35）。8人の状態は撮られていない（問題17）

## 問題の一覧（幅の記載がないものは両幅で同じ）

### 高
1. ホーム画面の右下（01〜03・12。04・05は背景に写る）の「127.0.0.1:8819/pad で、このコードを入力」と、08の共有欄「http://127.0.0.1:8819/」。127.0.0.1は表示している機械自身を指すアドレスで、スマホや受け取った人の端末からは開けない。手入力での参加と共有が成り立たない → 部屋の案内には同じネットワークから届くアドレスを、共有には公開サイトのURLを出す。本番に近い環境で撮り直して確かめる（撮影環境の疑い）

### 中
2. 語の途中の改行：01「多く取った人／の勝ち」、03「ふくらませ／る」、04「くだ／さい」、05「早／く」、08「入ってく／る」「コ／ピー」、09「確か／めて」→ 文節の切れ目でだけ折り返す。または1行に収まる長さに縮める
3. 02：1人目が入ると「はじめかた」の③が消え、大画面に次の一手が出ない → 参加者がいて開始前のあいだは「たろうさんのスマホで、遊ぶゲームを選んでください」を24px以上で、参加者欄の上に出す
4. 03：開始の合図「OK 決定で えらぶ」が約26px（1366は約17px）の淡い文字で、「決定で」の後に不要な空白がある → 32px以上の明るい文字にし、「スマホの［OK］で このゲームを選ぶ」と、誰が何を押すかを書く
5. 開発者向けの文言：03の説明「SDKの全体像を30秒で見せる、いちばん小さな見本。」、10の「（docs/operate.md）」、主役カードの「作者／ライセンス」の行（01〜03）→ 03は遊び方の説明に差し替える。10はファイル名を消す。作者とライセンスは詳細（05）だけに残す
6. 音の案内：01〜03では点線の枠で「ゲーム」見出しの横に割り込み、09〜11では上部の帯になる。上部の操作欄の「音 オン」とも意味が食い違う → 出し方を上部の帯1種類にそろえ、エラー画面では出さない。クリック前の操作欄は「音：まだ鳴りません」のように実際の状態を出す
7. 04：塗りの「外す」と、輪の付いた「やめる」が並び、どちらが選択中か一目で分からない → 選択中の印を1つに絞る（選ばれていないボタンは輪郭だけにし、選ばれたものだけを塗る）
8. 10：ただ一つのボタン「あとで試す」は、押すと何が起きるのか分からない → 「閉じる」か「もう一度試す」にする
9. 03：参加者がそろった後も、部屋コード（約95px）が画面で最大の文字のまま → 位置は変えずに、参加者が1人以上になったら字の高さを70px前後に下げ、主役カードの題名より目立たなくする
10. 参加の手入力案内（01〜03の右下）と音の案内が、1920で約20px、1366で約14px。24pxの目安を下回る → 1080pで24px以上（1366で約17px以上）にする

### 低
11. 01・03：説明文は「スティックで動いて」、タグは「十字キーとボタン」で食い違う → どちらかにそろえる
12. 02・03：棚の縮小画像の文字や図形が題名の裏に透ける（4択クイズの「愛知県と岐阜県」、ハローパッドの青い図形）→ 題名の下に敷く暗い帯を濃くする
13. 01・12：参加者0人のとき、棚の縮小画像が暗い灰色で、4本の見分けが題名頼みになる → 縮小画像を明るくする
14. 01・12：「はじめかた」の手順カードの「＞」が、押せるボタンに見える → 矢印を外すか、カードとカードの間に置く
15. 01：「ロック」が何を固定するのか、初見では分からない → 「参加を締め切る」など、目的の分かる名前にする
16. 主役カードの下端が01で約560px、02・03で約590pxと違う。選択を替えると棚が上下に動くおそれ（静止画では未確認）→ 主役カードの高さを固定する
17. 03（未撮影）：8人になると参加者の札が2行以上に折れ、画面の下にはみ出すおそれ → 8人の状態を撮って確かめる
18. 04：窓の幅が約1110pxで、ボタンが左に寄り、右半分が空く → 窓の幅を800px前後に縮める
19. 04・12：背景の暗さが足りず、QRと部屋コードがはっきり見える（とくに1366）→ 背景をもっと暗くする
20. 05：右の列の下側（約370px）が空き、中身は主役カードとほぼ同じ → 操作の図（どのボタンを押すか）を入れるか、窓の高さを詰める
21. 05：窓の左右の端から、背景の部屋コード「8」、QRの一部、「せん」の文字がのぞく → 背景をもっと暗くするか、窓を左右いっぱいに広げる
22. 06：アイコンの有無で、項目の書き出しが約46px（1366は約34px）ずれる → 全項目にアイコンを付けるか、アイコン分の空きを全項目にとる
23. 06：ゲームを離れる「ホームへ」がほかの項目と同じ見た目で、一時停止の中に「ライセンスとクレジット」がある → 「ホームへ」を区切り線で分け、ライセンスは外す
24. 07：行の幅が約1520px（1366は約1080px）で、名前と点数が約1100px（約770px）離れる → 1920では行の幅を1000px前後に縮める
25. 07：「0.9秒」に見出しがなく、何の時間か分からない → 「ゴールまで」などの見出しを付ける
26. 07：1位の強調が細い枠と淡い光だけで控えめ → 1位の行だけ、名前と点数を1.3倍ほどにする（動きは未確認）
27. 07（1366）：順位の行とボタンの間が約20pxしかなく、まとまりの切れ目が弱い → 40px前後あける
28. 07→08：結果の「共有」を押すと、結果ではなくサイトのURLを送る → ボタン名を「irori を紹介」などにする
29. 08：「リンクをコピー」だけが2列の左に1つ残る → 3つを横1列に並べるか、コピーを全幅にする
30. 09：部屋・参加者・点数が残るかどうかが書かれていない → 「部屋と参加者はそのままです」を一文足す
31. 11：新しい部屋では参加者がQRを読み直す必要があることが書かれていない → その一文を足す
32. 12：選べるのが「ここで続ける」だけ → 「このタブを閉じる」を足す
33. 部屋コードにBと8が両方使われている（「DB6P」「3WR8」）。3m先では見間違えやすい → B・8、S・5、O・0、I・1など、紛らわしい文字を使わない
34. 選ばれていないボタン（上部の操作欄）、棚のカード、メニュー項目の輪郭が背景に溶ける（推定 約1.5〜2:1）。文字で区別はできる → 輪郭を3:1前後まで明るくする
35. 淡い補足文字：主役カードの「作者」「ライセンス」（推定 約4:1）、07の「0.9秒」（推定 約4.5:1）、03の「つながっていません」（推定 約4:1）。1366では大きい文字の扱いにならず、4.5:1を下回るおそれ → 一段明るくする
36. 表記の揺れ：「音 オン」（上部の操作欄）と「音：オン」（06）、操作名の「ロック」と状態の「ロック：オフ」、07だけひらがなの見出し「けっか」→ 状態は「音：オン」の形に、見出しは漢字かな交じりにそろえる
37. 点線の枠が「まだ遊べないカード」（01・12）と「音の案内」（01〜03）の2つの意味で使われている → 点線はどちらか一方だけにする
38. エラー画面の組み方が2種類ある（09・12は左揃えの窓、10・11は中央揃えでロゴ付き）→ 意図した使い分けでなければ、どちらかにそろえる

## 撮影の疑い
- 「127.0.0.1」の表示（01〜05・08・12、両幅）：手元のサーバーで撮った可能性がある。本番に近い環境で撮り直して確かめる
- 音の案内が出たまま（01〜03・09〜11）：自動撮影で一度もクリックしていないためと考えられる。出し方の揺れ（問題6）は、撮影と関係なく残る
- 07の「0.9秒」：40回の連打に0.9秒は現実的でなく、試験用の値の可能性がある。見出しがない問題（問題25）は残る
- 部屋コードが幅ごとに違う（1920は「3WR8」「KFJW」、1366は「CR2S」「DB6P」）：撮影ごとに部屋を作り直したためと考えられ、不具合ではない
- 音と動き（輪の光り方、1位の演出、つなぎ直しの進み具合、画面の切り替え）は静止画では分からないため、未確認
