# R-security レビュー：費用の栓に迂回路があり、名前の数え方の食い違いでホストが止まる

2026-10-16、読み取りだけで行った。指摘は高1件・中2件・低6件。実装の担当の報告は使わず、コードを読み、手元の wrangler dev（8840〜8859番）・Playwright（Chromium 156・WebKit 27.2）・状態機械の直接の実行で確かめた。一時ファイルは mkdtemp の中だけに置き、終わったあと消した。レビュー中に画面のファイルが書き換わったので、行番号は 08:10 時点の内容に合わせた。

## 指摘の一覧

### 高1：既にある部屋への接続・入退室・ロックの切り替えを、どの栓も数えない

- 場所：`apps/edge/src/room.ts:93-107`（部屋があれば、接続を数えずに受ける）、`packages/room/src/core.ts:333-336`（待ち中の接続の数に上限がない）、`core.ts:455`・`:568`（入る・出るたびに保存）、`core.ts:521-525`（ロックの切り替えのたびに保存）、`core.ts:353-361`（速さの上限は接続ごとなので、つなぎ直すと満杯から始まる）。
- 再現：同じIPから、存在確認は30回で 429 になった。一方、既にある部屋へは hello のない接続200本がすべて開き、hello→bye の100往復が0.77秒ですべて通った。状態機械を直接動かすと、100往復で保存（persist）が200回、ロックの切り替え80回で保存が80回出た。部屋は自分で作れるので、他人の部屋のコードも要らない。
- 影響（計算）：この速さなら1台で毎秒約260行を書き込む。無料プランの書き込みの枠（1日10万行）は約6〜7分で尽き、その日は書き込みが止まって新しい部屋を作れなくなる見込み。有料プランでは1往復が約2.5マイクロドルで、同じ回数の GET の連打の約8倍の費用になる。`docs/operate.md:34` の「1日の部屋数を絞れば、最悪の日でも数ドル」は、部屋1つの中に上限がないので成り立たない。`docs/security.md:14` の「接続に上限」も実装にない。CPU への影響は小さかった（待ち中の接続1万本で、入力1件の処理が1µsから8µs）。
- あわせて：存在しない部屋への WebSocket は、部屋の Durable Object を起こしてから数える（`room.ts:93-98`）。HTTP の存在確認（`apps/edge/src/index.ts:47`）は先に数えるので、順序がそろっていない。
- 直し方の案：WebSocket の受け付けを IP ごとに数える（存在確認とは別の枠）。部屋ごとに、待ち中の接続（例：16本）と1分あたりの入室を縛る。席とロックの保存は目覚まし（alarm）にまとめ、数秒に1回にする。operate.md の見積もりを直す。

### 中1：書記素の数え方が実行環境で違い、名前1つでホストが自分の部屋に戻れなくなる

- 場所：`packages/protocol/src/names.ts:7-27`（Intl.Segmenter に頼る）、`packages/protocol/src/validate.ts:93-97`・`:343-351`（受け手も書記素で縛る）、`packages/room-client/src/socket.ts:282-291`（通らないフレームは黙って捨てる。welcome も同じ）。
- 再現：ミャンマー文字・クメール文字・ジャワ文字・バリ文字の結合子音（例：U+1000 U+1039 U+1000）を、Node 24（ICU 77.1・Unicode 16.0）は2書記素、Chromium 156・WebKit 27.2・手元の workerd は1書記素と数えた。この文字を13個並べた名前で参加すると、中継は12個（36符号単位）を残した。Node で動かした本物の RoomSocket（ホスト役）は `joined` を「12より長い」として捨てた。つなぎ直したホストは `welcome` まで捨てて `connecting` から進まず、中継からは `pad?` だけが届いた。
- 影響：ホストのブラウザの ICU が中継より古いと、参加者が見えず、外せず、読み込み直しても自分の部屋に戻れない。部屋のコードを知る人なら誰でも起こせるうえ、その言語の名前なら悪意がなくても起きる。ここまでは再現した。同じ仕組みから、古いスマホは自分の welcome を捨てて入れず、逆にブラウザのほうが新しくなると、ホストが通したゲームのラベルを中継が形式違反として捨て、5秒に20回で接続を切ると推定する（未再現）。
- 直し方の案：受け手は、中継が整えた文字列を拒まず、表示の時に切る（名前1つで welcome を丸ごと捨てない）。上限の判定は、環境に依らない量（符号位置の数かUTF-8のバイト数）にそろえ、書記素は表示の切り詰めだけに使う。

### 中2：`docs/legal/data-handling.md` に、名前・入力・傾きがゲームへ渡ることが書かれていない

- 場所：文書の `:7`・`:11`・`:20`。実装は `apps/web/src/host/console.ts:358`（名前を init で枠へ渡す）、`console.ts:256`（入力を枠へ渡す）、`packages/host-bridge/src/frame.ts:162`。
- 何が起きるか：ニックネームと入力（傾きの値を含む）は、ゲームの枠に渡る。外部のゲームは自分のオリジンでネットワークを使えるので、その運営者のサーバーへ送れる。文書の流れは「スマホ→Worker→ホストの画面」だけで、外部のゲームは「IPアドレスなどを見られる」としか書いていない。開く前の確認（`apps/web/src/host/messages.ts:101`）も、通信することだけを伝える。運営者がこの表をもとにプライバシーの説明を書くと、第三者への提供が抜け落ちる。
- 直し方の案：表の流れに「→ゲームの枠（外部のゲームでは、その運営者のサーバーにも送れる）」を足す。確認の文にも、名前と操作がゲームに渡ることを書く。

### 低（6件）

1. 名前は12書記素でも約430バイトまで通る（`names.ts:58-71`、`validate.ts:291-294`）。結合記号を積んだ名前を、中継はそのまま残した（12書記素・221符号単位・438バイト）。WebKit では、切っていない案内文（`.start-prompt`）の上へ記号がはみ出した。外す確認の見出し（`apps/web/src/host/view-panels.ts:104`）も切っていない。案：1書記素あたりの結合記号の数か名前のバイト数で縛り、名前の箱を `overflow: clip` にする。
2. 休止からの復元で、部屋が最大60秒早く閉じる（`core.ts:295-298`）。最後の操作の時刻を60秒ごとにしか保存しないため。状態機械で、最後の入力が59秒・保存値が2ミリ秒のとき、20分30秒の時点で、通常の経路は部屋を残し、復元の経路は閉じた。案：時刻を接続の付属情報に持たせ、復元のときに照らす。
3. 1日の部屋数の栓を、少ない手間で使い切れる。IPv6 は /64 を1人と数える（`apps/edge/src/policy.ts:69-86`）ので、/48（無料のトンネルでも得られる）なら6.5万人分になり、2,000件（`apps/edge/src/limiter.ts:69`）は数分で尽きる。別サイトからの `POST /api/rooms` も 201 で通り（実測）、WebSocket も Origin を見ないので、訪問者のIPを借りても減らせる。案：/48 単位でも数える。POST には独自のヘッダーか `Sec-Fetch-Site: same-origin` を求める。WebSocket では Origin を確かめる。
4. IP のハッシュの塩を、ハッシュと同じ保存領域に置いている（`limiter.ts:55`・`:87-91`）。保存を読める人なら、IPv4（約43億通り）は総当たりで戻せる。消えるのは翌日（UTC）の最初の要求のとき。文書（`data-handling.md:12`）の「生の値は保存しない」は正しいが、匿名ではなく仮名である、と書くほうが正確。
5. 試遊サーバー（`tools/playtest-server.mjs:416-453`）は 127.0.0.1 で待ち受けるが、Host と Origin を見ない。ポートを当てられれば、開発者が開いた別のページから単純な POST で操作でき、DNS の付け替えで `/state` も読める（疑い・未再現）。案：Host を確かめ、Origin 付きの要求を断る。
6. ゲームの途中で抜けた人の席番号を、あとから来た人が引き継ぐ不具合は、07:58 のビルドで再現した（Cさんがゲームのコントローラーを受け取り、結果にもBさんの枠で載った）。07:59 に入った `apps/web/src/host/lineup.ts` で直り、最新のビルドでは再現しない。残るのは、ホストが切れているあいだに同じ名前で入れ替わった場合で、`lineup.ts:30-41` の注記どおり見分けられない。中継が席ごとの通し番号を渡せば閉じられる。

- 動かしたもの：`npm run typecheck`（終了コード0）、`npm test`（vitest 855件・node --test 48件がすべて成功）、`npm audit`（本番の依存も全体も0件）。`tools/lib/edge-server.mjs` の buildWeb・startEdge で手元の中継を2回起こし、生の WebSocket・本物の RoomSocket・Playwright で上の再現を行った。状態機械（RoomCore）と文字列処理は esbuild でまとめて直接動かした。

## 問題がなかったもの（確かめた方法）

- XSS：ソース全体で innerHTML・outerHTML・insertAdjacentHTML・document.write・srcdoc・eval・new Function・`javascript:` を検索し、該当なし。`h()` は2つとも Text ノードで入れる。名前は `nameEl`・`withName`、読み上げの名前は setAttribute。外へのリンクは `rel="noopener noreferrer"`、共有のURLは encodeURIComponent で組む。同梱ゲームの名前は canvas の fillText か textContent で描く。
- 文節の分割（phrase.ts と BudouX の写し）：使うのは画面が持つ文言と、審査済みの登録情報の題名だけで、名前とゲームの文字列には使っていない。10万字でも chunks は37ms、正規表現はどれも1ms以下（線形）。モデルは13種・1,619個のキーで、`__proto__` もサロゲートの対を割る文字もない。
- 隔離枠：握手は `event.source`・オリジン・1回きりの3つで受ける。以後は MessagePort だけで、毎秒100件を超えると枠を止める。SDK も `ev.source === parent` を確かめる。sandbox は src より先に付ける。`allow-same-origin` は別オリジンの外部ゲームだけ。`?dev=` はローカルとLANのホスト名でだけ効く。コンソールのオリジンにあるHTMLは、`frame-ancestors 'none'`（`/`・`/pad`）か CSP の sandbox（`/games/*`）のどちらかで守られている。パスを書き換えた要求（`/%67ames/…`・`/games%2F…`・`//games/…`）も、本来のパスへ 307 で返るだけだった。そのため、外部のゲームが枠ごとコンソールのオリジンへ移っても、守りのないHTMLは開けない。
- なりすまし・認可：席番号は接続から決める。スマホの `in` に `p` があれば拒み、役割は最初のフレームで固定する。ホストの鍵は256ビット、再開の札は128ビットで、どちらも getRandomValues から作る。比較は SHA-256 のハッシュどうしを定数時間で行う。`__proto__` は知らないキーとして拒む。
- 状態機械：入れ替え・外す・猶予切れ・ロック・満員・復元の経路を読み、入退室・ロック・復元は直接動かした。復元は閉じかけの接続を除き、同じ席に複数あれば新しいほうを残す。席の二重取りと行方不明の席は見つからなかった（例外は低2）。
- ヘッダー（実測）：`/` と `/pad` は script-src 'self'・frame-ancestors 'none'・nosniff・no-referrer。Set-Cookie はなく、`/api` に CORS もない（OPTIONS は 405）。サーバーにログの出力も外部への送信もない。
- 道具：子プロセスはシェルを通さず、配列で渡す。一時フォルダは mkdtemp で作り、後で消している。`--ip 0.0.0.0` で起動しても、wrangler のデバッガーは既定で 127.0.0.1 にだけ開く（wrangler の該当ソースで確認）。
- CI：権限は `contents: read`、Actions はハッシュで固定、`persist-credentials: false`、`pull_request_target` は使っていない。
