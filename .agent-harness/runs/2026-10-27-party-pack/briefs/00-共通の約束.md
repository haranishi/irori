# 全担当に共通の約束（パーティーパック・第2弾）

irori は、大画面のブラウザをゲーム機にして、スマホをコントローラーにするOSSのWebゲーム機。この指示書は、担当ごとの指示書と一緒に読む。作業ルートはリポジトリのルート。`.kiro/specs/party-game-pack/` に、要件・設計・各ゲームの規則がある。まず担当の指示書が挙げる文書を読むこと。

## 読むもの（全員）
- `docs/sdk.md`（ゲームの作り方と決まり）、`docs/pad.md`（コントローラーの種類）、`.kiro/specs/party-game-pack/design-contracts.md`。
- 書き方の手本：`games/lantern-market/`（`logic.js` は `createGame` / `updateGame` / `publicView` と、`{state, effects}` を返す純粋関数。`logic.test.js` の試験の形）。

## 所有する場所と禁止
- 自分の担当の「所有する場所」だけを書く。ほかは読むだけ。ほかが必要になったら、変えずに報告に書く。
- `git commit`・`git push`・依存の追加（`npm install`）・生成物（`apps/web/public/**` `dist/**`）の編集・`node_modules` の編集は禁止。
- 通信の型と上限（`packages/protocol`）は変えない。変えたくなったら報告に書く。

## どのファイルにも書かないもの（`npm run check` が拒否する）
- 他社の名称・商品名・参考にしたサイトの識別子。禁止語は `tools/check-rights.mjs` の一覧が持つ。札遊びや人狼の市販品の名前も書かない。
- 私的な絶対パス（ホームの下、OSの一時フォルダ、作業フォルダ名）。パスはリポジトリのルートからの相対で書く。
- 音声・書体のファイル、外部URLの読み込み（`https://` の script・link・img・import・fetch）。見た目・音・文は自作する。
- 文書（`.md`）は1ファイル100行以内。コードを消したら失われる情報だけを書き、コードを読めば分かることは書かない。

## コードの決まり
- `// @ts-check` と JSDoc の型。識別子（札・席・選択肢）は `^[a-z0-9_-]{1,24}$`（小文字だけ）。`nonce` は `^[a-z0-9]{1,8}$`。
- 乱数は、種つきの関数（例：mulberry32）を自分で持ち、状態に入れる。判定で `Math.random` と `Date.now` を使わない（同じ入力は同じ結果）。
- 秘密（手札・役職・夜の行動・確定前の選択）は、`{t:'pad', to: 席, spec}` の席ごとの効果だけで送る。`'*'` や全員宛に出さない。`publicView` に秘密を入れない。
- 席の扱い：`online` が偽の席は待つ（点・手札を保つ）。`players` から消えた席だけを退出として扱う。`end` は1回だけ送る。
- 試験は vitest。実行：`npx vitest run --config vitest.games.config.ts games/<id>`。実行された件数を確かめる（0件の成功は成功でない）。

## 試験の質
- 試験を足したら、判定を一時的に壊して（1か所の比較を逆にするなど）試験が赤くなることを確かめ、元に戻す。何を壊して何が赤くなったかを報告に書く。
- 全探索・保存則・無作為な対戦（種を変えて多数回）で、規則の抜けを探す。見つけた不具合は直し、直した理由を試験の名前か注釈に残す（バグ修正の試験には「なぜ失敗したか」を書く）。

## 担当ごとの制約
- Codex の担当：ブラウザ・localhost・サーバーは起動できない。静的な検査と単体の試験だけを行い、ブラウザが要る確認は「書いて、メインに渡す」と報告する。
- Opus の担当：ブラウザで確かめる。開発サーバー（`npm run dev`）の `/games/<id>/?mock=N` で仮想プレイヤーを使える。画像は縮めてから見る（390・768・1440の3幅）。Playwright のブラウザが無ければ `npx playwright install chromium`。

## 報告（`reports/<担当名>.md`、100行以内）
①変更したファイルの一覧 ②実行したコマンドと件数（成功・失敗・スキップ）③壊して確かめた変異の一覧 ④設計への提案・未解決・気づいた規則の穴 ⑤人が確かめるべきこと。完了は、自己申告でなく、実行したコマンドと出力の件数で示す。
途中で止まるときのために、進捗を `reports/<担当名>.md` に随時追記する（別の担当が続きから引き継ぐ）。
