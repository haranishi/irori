# 担当C1：大富豪の判定（Codex）

`00-共通の約束.md` を先に読む。そのあと `.kiro/specs/party-game-pack/game-daifugo.md` と、`requirements.md` の要件 8・4・5 を読む。

## 所有する場所（これだけを書く）
`games/daifugo/logic.js`、`games/daifugo/cards.js`、`games/daifugo/logic.test.js`、`games/daifugo/cards.test.js`、`tools/mutations/specs/party-pack-daifugo.json`（変異の仕様。形は `tools/mutations/specs/competitive-pack.json`）、`reports/大富豪の判定.md`。画面（`view.js` `main.js` `index.html` `style.css`）は別の担当が作る。作らない。

## 作るもの
- `cards.js`：`makeRng(seed)`（種つきの乱数）、`shuffle(cards, rng)`（Fisher-Yates。範囲の誤りで偏らない）、`buildDeck()`（54枚）、`strength(card, revolution)`、`classify(cards)`（セットの数・枚数・ジョーカーの扱い）、`legalPlays(hand, table, revolution)`、`isLegal(play, table, revolution)`。
- `logic.js`：`createGame(init)`・`updateGame(state, event)`・`publicView(state)`。`init` は `{players, leader, environment, paused, nonce, seed}`。イベントは `input`（`k:'btn'` の開始、`k:'tiles'` の出す・パス）・`players`・`menu`・`environment`。効果は `{t:'pad', to, spec}`・`{t:'cue', name, v?}`・`{t:'vibrate', to, ms}`・`{t:'end', results, options}`。
- 段階：`intro`（リーダーに `pad` の「はじめる」ボタン、ほかは `wait`。手本は `games/lantern-market/logic.js` の `control`）→ `play` → `ended`。3人未満・9人以上では開始させない。
- スマホの画面は、設計書どおり `tiles`（自分の番：手札・`max` 4・`ok`「出す」・`pass`「パス」（場が空なら付けない）・どの出し方にも入れない札は `off`・`note` に場と順番。番でない：`disabled`）。札の `id` は `d{nonce}_{改訂番号}_{札}` で24文字以内。拒否したら、同じ画面を理由つきの `note` で送り直す。
- `publicView`：`{phase, seats:[{id,name,count,passed,rank,left,online}], table:{cards,n,by}|null, turn, revolution, events:[{seq,type,...}], leader, canBegin, outcome}`。手札の中身を含まない。`events` は `play` `pass` `sweep` `revolution` `finish` の連番つき。
- 効果音の依頼：配札で `deal`、出すたびに `place`、場が流れたら `sweep`、革命で `revolution`、上がりで `win`、最下位が決まったとき `lose`。上がった人以外の番の変化では鳴らさない。
- 結果：上がった順に順位。`score` は人数−順位+1。`display: 'record'`、`label` は「大富豪」「富豪」「平民」「貧民」「大貧民」（3人は大富豪・平民・大貧民、4人は大富豪・富豪・貧民・大貧民、5人以上は間を平民で埋める）。退出した席は `ranked: false`、`label: '退出'`。
- 設計書にない判断（あいまいな規則）は、設計書の文言に最も近い解釈にし、報告の④に書く。

## 試験で守るもの
設計書の「試験」の節のとおり。特に、①無作為な対戦（3〜8人×各2000回、種を変えて）で、各手の後に札の合計が54枚・重複なし・必ず終了・上がり順が全員の並べ替え ②`legalPlays` が全探索（小さな手札のすべての部分集合）と一致 ③ジョーカーの扱い（単独・2枚組・代わり・8切り・4枚革命）④拒否が状態を変えない（deep equal）⑤`end` が1回 ⑥どの席宛の `pad` にも他席の札が入らない。変異（比較・保存・拒否の1か所を壊す）を `party-pack-daifugo.json` に書き、`npm run mutations` の実行器で全部赤くなることを確かめて報告に書く。席が消えたあとの順位は設計書のとおり（順位を付けられる人が2人未満なら未成立）。 型検査（`npm run typecheck:games`）は、`tiles` の型が SDK に入るまで通らない。通らないときは報告に書くだけでよい。
