# 担当C2：ババ抜きの判定（Codex）

`00-共通の約束.md` を先に読む。そのあと `.kiro/specs/party-game-pack/game-old-maid.md` と、`requirements.md` の要件 9・4・5 を読む。

## 所有する場所（これだけを書く）
`games/old-maid/logic.js`、`games/old-maid/cards.js`、`games/old-maid/logic.test.js`、`games/old-maid/cards.test.js`、`tools/mutations/specs/party-pack-old-maid.json`（変異の仕様。形は `tools/mutations/specs/competitive-pack.json`）、`reports/ババ抜きの判定.md`。画面は別の担当が作る。作らない。

## 作るもの
- `cards.js`：`makeRng(seed)`、`shuffle(cards, rng)`（Fisher-Yates。偏らない）、`buildDeck()`（53枚）、`dealAndPair(seatIds, seed)`（配札と自動のペア捨て。各席の手札・捨て札・配札で上がった席を返す）、`pairOff(hand)`（同じ数のペアを捨てる）。
- `logic.js`：`createGame(init)`・`updateGame(state, event)`・`publicView(state)`。`init` は `{players, leader, environment, paused, nonce, seed}`。イベントは `input`（`k:'btn'` の開始、`k:'tiles'` の「ひく」）・`players`・`menu`・`environment`。効果は `{t:'pad', to, spec}`・`{t:'cue', name, v?}`・`{t:'vibrate', to, ms}`・`{t:'end', results, options}`。
- 段階：`intro`（リーダーに `pad` の「はじめる」、ほかは `wait`）→ `play` → `ended`。2人未満・9人以上では開始させない。
- 番：引く人は、席の順で次の手札のある人から1枚を引く。引かれる側の並びは、番の始まりごとに種つきの乱数で並べ替える。引く札は、位置の番号の識別子 `o{nonce}_{改訂番号}_{位置}` で表す（札の中身を入れない）。
- スマホの画面：引く人は `tiles`（相手の枚数ぶんの「1」「2」…、`max` 1、`ok`「ひく」、`note` に自分の手札の文字）。引かれる人は `wait`（見出し「◯◯さんが札をひいています」、本文に自分の手札）。引いたあとは、引いた人にだけ `wait`（「ひいた札：♥7。ペア成立！」など）を送る。ほかの人は `tiles` を `disabled`（見るだけ）。
- `publicView`：`{phase, seats:[{id,name,count,rank,left,online}], turn:{from,to}|null, discard:[...](ペアの捨て札のみ), events:[{seq,type,...}], leader, canBegin, outcome}`。手札の中身とジョーカーの所在を含まない。`events` は `draw`（札の中身なし）`pair`（捨てた2枚）`out` の連番つき。
- 効果音：配札 `deal`、引く `flip`、ペア成立 `place`、上がり `win`、最下位 `lose`。
- 結果：上がった順に順位（最後の人が最下位）。`score` は人数−順位+1、`display: 'record'`、`label` は「1位」〜「最下位」の形。退出した席は `ranked: false`、`label: '退出'`。
- 席が消えたときの扱いは設計書のとおり（ジョーカーを持っていたら、残りの誰かへ種つきの乱数で移す）。あいまいな点は、設計書に最も近い解釈にし、報告の④に書く。

## 試験で守るもの
①札の保存：配札後と各手の後に、手札・捨て札・除外の合計が53枚で重複なし。ジョーカーは常に1枚 ②`pairOff` の数え方（1〜4枚）と、配札で上がる人 ③シャッフルの偏り（小さな札の山で全順列の頻度を調べる）④無作為な対戦（2〜8人×各2000回）で必ず終わり、上がった順が全員の並べ替えで、最後の人がジョーカー持ち ⑤拒否（他席・番外・古い識別子・範囲外・重複）が状態を変えない ⑥席の消失・接続切れ・一時停止・`end` が1回 ⑦どの席宛の `pad` にも、他席の手札や、引く札の中身が入らない。変異を `party-pack-old-maid.json` に書き、`npm run mutations` の実行器で全部赤くなることを確かめて報告に書く。席が消えたあとの順位は設計書のとおり（順位を付けられる人が2人未満なら未成立）。 型検査（`npm run typecheck:games`）は、`tiles` の型が SDK に入るまで通らない。通らないときは報告に書くだけでよい。
