# 追補C1：大富豪の判定に tiles の token を使わせる（Codex）

`00-共通の約束.md` を先に読む。前回の自分の報告（`reports/大富豪の判定.md`）の④にある「パスは `ids:[]` で改訂番号を運べず、遅延した旧画面のパスを識別できない」への対応。プロトコル側は**実装済み**：`tiles` の指定に `token`（任意）、`tiles` の入力に `t`（任意）がある。`pad-ui` は、出している画面の `token` を、決定とパスの入力の `t` に載せて返す（担当 SdkBridge が別途実装中）。

## 所有する場所
前回と同じ：`games/daifugo/{logic,cards}.js` と試験、`tools/mutations/specs/party-pack-daifugo.json`、報告。ほかは編集しない。

## 直すこと
- 席ごとに送る `tiles` のすべてに `token` を付ける。値は `d{nonce}_{改訂番号}` の形（24文字以内）。改訂番号が変わったら `token` も変わる。
- `k:'tiles'` の入力は、`t` が、その席にいま出している画面の `token` と**一致するときだけ**受ける。`t` が無い・違う場合は、状態を変えずに無視する（理由の `note` を送り直さない。古い画面の入力だから）。
- 試験：古い `t` のパス・古い `t` の出す・`t` の無い入力が、状態を変えずに無視されること。番が一周して同じ席に戻ったあとでも、古い `t` が拒否されること。変異（`t` の検査を外す）を `party-pack-daifugo.json` に足し、赤くなることを確かめる。
- 既存の単体試験の入力には `t` を足して通す。
- 実行時間：無作為な対戦の試験は、いま全体で約100秒かかる。人数ごと2000回の既定は保ったまま、環境変数（例：`IRORI_SIM_GAMES`）で回数を変えられるようにし、**既定は人数ごと300回**に下げる（CI の長い周回は、環境変数で2000回に戻す）。保存則・終了・順位の検査の中身は削らない。報告に、既定と2000回それぞれの所要時間を書く。

## 走らせるもの
`npx vitest run --config vitest.games.config.ts games/daifugo`、`npm run mutations -- --only party-pack-daifugo-`。件数を報告する（`reports/大富豪の判定.md` の末尾に追記）。型検査は、SDK の型が追いつくまで通らないことがある。通らなければ報告に書くだけでよい。
