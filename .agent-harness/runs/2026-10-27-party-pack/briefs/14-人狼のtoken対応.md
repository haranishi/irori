# 追補C3：人狼の判定に tiles の token を使わせる（Codex）

`00-共通の約束.md` を先に読む。前回の自分の報告（`reports/人狼の判定.md`）の「未解決：空決定・パスの古い入力の識別」への対応。プロトコル側は**実装済み**：`tiles` の指定に `token`（任意）、`tiles` の入力に `t`（任意）がある。`pad-ui` は、出している画面の `token` を、決定とパスの入力の `t` に載せて返す（担当 SdkBridge が別途実装中）。

## 所有する場所
前回と同じ：`games/moon-village/{logic,roles}.js` と試験、`tools/mutations/specs/party-pack-moon-village.json`、報告。ほかは編集しない。

## 直すこと
- 席ごとに送る `tiles` のすべて（役の確認・夜・昼のリーダーの操作・投票・決選）に `token` を付ける。値は `w{nonce}_{改訂番号}` の形（24文字以内）。画面を送り直すたびに、改訂番号が変わるなら `token` も変わる。
- `k:'tiles'` の入力は、`t` が、その席にいま出している画面の `token` と**一致するときだけ**受ける。無い・違う場合は、状態を変えずに無視する。特に、夜の「役を見る」・昼の「＋1分」・投票の「棄権」は、`ids` が空のパスなので、`t` の検査が唯一の見分けになる。
- 試験：前の段階で出した画面の `t` を持つ入力（夜の「役を見る」→投票の棄権、昼の「＋1分」→投票、役の確認の決定→夜）が、状態を変えずに無視されること。`t` の無い入力も同じ。変異（`t` の検査を外す）を `party-pack-moon-village.json` に足し、赤くなることを確かめる。
- 既存の単体試験の入力には `t` を足して通す。
- 実行時間：無作為な対戦の試験の既定を、環境変数（例：`IRORI_SIM_GAMES`）で変えられるようにし、既定を人数ごと500回に下げる（2000回は環境変数で戻せる）。検査の中身は削らない。報告に、既定と2000回それぞれの所要時間を書く。

## 走らせるもの
`npx vitest run --config vitest.games.config.ts games/moon-village`、`npm run mutations -- --only party-pack-moon-village-`。件数を `reports/人狼の判定.md` の末尾に追記する。型検査は、SDK の型が追いつくまで通らないことがある。通らなければ報告に書くだけでよい。
