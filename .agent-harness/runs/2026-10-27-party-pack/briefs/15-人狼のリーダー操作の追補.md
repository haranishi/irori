# 追補C3：人狼の夜明けと処刑のあとに、リーダーのスマホから進める（Codex）

`00-共通の約束.md` を先に読む。前回の自分の報告（`reports/人狼の判定.md`）と、`.kiro/specs/party-game-pack/game-werewolf.md` を読み直す。

## 見つかった欠陥
実ホスト＋スマホの通しの試験で、**夜明け（`dawn`）と処刑（`exec`）のあと、全員のスマホが `wait` のままで、リーダーが進める操作が無い**ことが分かった。いまは、大画面のボタン（`main.js` の `continueDay`）を押す以外に進める手段が無い。大画面は見るための画面で、進行はスマホで行う設計（昼の「投票へ」・役の確認など、ほかの段階はリーダーのスマホに `tiles` の `ok` がある）なので、ここも同じにする。

## 所有する場所
前回と同じ：`games/moon-village/{logic,roles}.js` と試験、`tools/mutations/specs/party-pack-moon-village.json`、報告。画面（`view.js` `main.js` `index.html` `style.css` `view.test.js`）は別の担当が持つが、**この修正で壊れる箇所だけ**は、最小の直しを許す（報告に書く）。

## 直すこと
- `dawn` と `exec` で、リーダーの席にだけ `tiles`（`tiles: []`・`ok`「つづける」・`note` に発表の要約）を送る。ほかの席は、これまでどおり `wait`。`token` を付け、`t` が合わない入力は無視する（前回の token 対応のとおり）。
- リーダーの `ids: []`・`pass` なしの入力（`t` 一致）で、`dawn`→`day`、`exec`→次の夜または終了、へ進む。いまの `continueDay` の入力（大画面のボタンからの合成入力）も、そのまま動くようにする（マウスで押せる環境のための補助）。
- リーダーが脱落・退出・切断しているとき：リーダーの席は脱落しても進行の操作を持つ（昼の時計と同じ扱い）。リーダーの席が消えたら、生存者の最も小さい席番号が新しいリーダーになる、という既存の規則があればそれに従い、無ければ設計書に最も近い解釈にして報告に書く。
- 試験：リーダー以外の入力・古い `t`・`tiles` が空でない入力は無視される。リーダーの入力で進む。夜明けの発表が `wait` ではなくなるので、秘匿の走査（`pad` の形・役職の語）も更新して通す。変異（リーダー判定を外す）を足し、赤くなることを確かめる。

`npx vitest run --config vitest.games.config.ts games/moon-village`、`npm run mutations -- --only party-pack-moon-village-`、`npm run typecheck:games`。件数を報告の末尾に追記する。
