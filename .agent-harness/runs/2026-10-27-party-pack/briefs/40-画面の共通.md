# 画面担当（大富豪・ババ抜き・人狼）に共通の指示

`00-共通の約束.md` を先に読む。そのあと、担当のゲームの設計書（`.kiro/specs/party-game-pack/game-<名前>.md`）、`design-contracts.md`、要件 6、判定の担当の報告（`reports/<名前>の判定.md`）、`games/<id>/logic.js` の公開された形（`createGame` `updateGame` `publicView`・効果の種類）を読む。判定（`logic.js` `cards.js` `roles.js`）は変えない。変えたくなったら報告に書く。

## 作るもの（所有：`games/<id>/{index.html,style.css,main.js,view.js,README.md}` と `registry/games/<id>.json`）
- `main.js`：手本は `games/lantern-market/main.js`。`connect()` のあと、能力 `pad-tiles-v1`・`result-options-v1`・`host-environment-v1` が無ければ、`wait`（見出し「更新が必要です」）を出して `ready()` だけ呼んで待つ。`createGame` に、`players`・`leader`・`environment`・`paused`・`nonce`（小文字英数8字以内、毎回新しく）・`seed`（`crypto.getRandomValues` から）を渡す。`irori.on` の `input` `players` `pause` `resume` `environment` を `updateGame` へ流し、返った効果を実行する：`pad` は `irori.setPad(spec, 席)`、`cue` は `irori.cue?.(名前, 強さ)`（無ければ何もしない）、`vibrate` は `irori.vibrate`、`end` は `irori.end(results, options)`（1回だけ）。人狼は、止まっていない間だけ `tick` を送る。`ready()` は最初の画面が出せたら呼ぶ。
- `view.js`：`publicView` の値だけを受け取って描く（秘密を持っていない）。文字はすべて `textContent`。画面の更新は、変わったところだけ。段階名を `document.documentElement.dataset.phase` に出す（通しの試験とサムネイルの道具が読む。判定の `phase` と同じ名前。手本は `games/lantern-market/view.js`）。対応していない旧ホストでは `unsupported`、つながらないときは `error`。
- 画面の質：囲炉裏の暖色（`docs/identity.md` と既存ゲームの `style.css` に合わせる）。色だけで意味を伝えない（柄・数・文字・印を併用）。本文16px以上、コントラストは AA（axe の違反0件）。幅390・768・1440で欠け・重なり・横スクロールなし。キーボードの焦点が見える。`prefers-reduced-motion` で、揺れ・飛散・点滅・大きな移動をやめ、短いフェードだけにする。
- 手触り：小さな反応を重ねる（移動・拡大のはね返り・光・音の依頼・振動）。重要な出来事ほど強く、日常の動作は控えめに。動きは行き過ぎてから戻す（イージング）。反応は短く、入力を止めない。
- `README.md`（日本語・100行以内）：遊び方、仮想プレイヤーでの試し方（`/games/<id>/?mock=N`、キーの割り当て）、規則の要点、独自の表現であること。他社の名称を書かない。
- `registry/games/<id>.json`：手本は `registry/games/lantern-market.json`。`added` は `2026-10-27`、`thumbnail` は `<id>.jpg`（メインが撮る。まだ無くてよい）、`pads` は使う種類、`sdk` は 1、`rating` は `all`。題名と紹介は日英。

## ブラウザで確かめる（3周まで）
開発サーバーは `npm run dev` を使わず、`python3 -m http.server <ポート> --directory games` を自分で起動し、自分のPIDだけ止める。`/<id>/?mock=N`（N は人数）で開く。Playwright で、配札・番・演出・終了・再戦まで通し、390・768・1440の3幅で撮って（縮めて）見る。見ること：欠け・重なり・読みにくさ・演出の自然さ・秘匿（共用画面に秘密が出ない）・一時停止で動きが止まること。直して再撮影。撮影のスクリプトはスクラッチに置き、リポジトリに入れない。

## サムネイルの手順（報告に書く）
サムネイルはメインが撮影の道具で撮る。ゲームが一番映える状態へ至る操作（キー入力・クリックの列と待ち時間・人数）を、報告に「撮影の手順」として書く。

## 完了
仮想プレイヤーで最初から結果・再戦まで遊べ、3幅で崩れず、`npm run typecheck:games` と担当の単体試験が通る（`tiles` の型が SDK に入ったあと）。報告（`reports/<名前>の画面.md`）に、撮った画像の観察と直したこと、人が確かめるべきこと（実機・音・遊び心地）を書く。
