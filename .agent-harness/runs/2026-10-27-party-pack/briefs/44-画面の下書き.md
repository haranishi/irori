# 画面の下書き（Codex・ブラウザなし）：大富豪・人狼

`00-共通の約束.md` → `40-画面の共通.md` → 担当ゲームの指示書（大富豪＝`41-大富豪の画面.md`、人狼＝`43-人狼の画面.md`）の順に読む。この指示書は、`40` の「ブラウザで確かめる」と「担当の制約」を**上書きする**。

## 立場
Codex はブラウザもサーバーも使えない。あなたの仕事は、**動く骨組みと、読める見た目の下書き**を作ること。仕上げ（実ブラウザでの撮影・直し・演出の磨き）は、このあと別の担当（Opus）が行う。だから、ほかの担当が引き継げるよう、構造を素直に保ち、画面の部品・クラス名・段階ごとの見た目の意図を `README.md` ではなく報告に書く。

## 作るもの（所有は `40` と同じ）
- `games/<id>/{index.html,style.css,main.js,view.js,README.md}` と `registry/games/<id>.json`。`40` の `main.js` の接続の約束（能力の確認・効果の実行・`tick`・`dataset.phase`）を、すべて満たす。
- `games/<id>/view.test.js`（`// @vitest-environment happy-dom` を先頭に書く）：`publicView` の値から、全段階の画面が**例外なく**描かれ、必要な文字が `textContent` で出て、秘密が出ない（人狼：終了前に役職の語が DOM のどこにも無い。大富豪：他席の手札の文字が無い）ことを確かめる。`createView(stage, status)` と `main.js` の接続は、`irori.js` の mock（`connect()` を単体で呼ぶと仮想プレイヤーになる）か、小さな偽物で通す。
- 見た目の下書き：`40` の画面の質（暖色・色以外の手がかり・16px以上・動きを減らす設定）を、CSS の値として実装する。演出は、CSS の `transition`・`@keyframes` で、動きを減らす設定では切る形にする。実際の見え方は確かめられないので、「意図」を CSS のコメントと報告に書く。

## 走らせるもの
`npx vitest run --config vitest.games.config.ts games/<id>`、`npm run typecheck:games`、`node tools/check-docs.mjs`、`node tools/check-rights.mjs`、`node tools/check-registry.mjs`。件数を報告（`reports/<名前>の画面.md`。100行以内）。「ブラウザで未確認」の項目を、Opus への引き継ぎとして列挙する。
