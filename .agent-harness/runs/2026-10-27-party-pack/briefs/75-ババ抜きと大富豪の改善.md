# 追補D3：ババ抜きと大富豪の改善（実際に遊んだ評価担当の指摘・改善の1周目）（Codex）

`00-共通の約束.md` を先に読む。前回の報告（`reports/ババ抜きの判定.md`・`reports/追補D1.md`）も読み直す。

## 所有する場所
`games/old-maid/`・`games/daifugo/`（画面・試験を含む）、`tools/mutations/specs/party-pack-old-maid.json`・`party-pack-daifugo.json`、`reports/追補D3.md`。**`tests/e2e/` は触らない**（メインが持つ）。通信の型・ホスト・pad-ui も変えない。E2E の試験が頼っていそうな文字（`最下位`・`退出`・`ひいた札`・`あなた：` など）を変えたら、`tests/e2e/console/party-pack.spec.ts` を grep して、影響する行を報告に書く。

## 評価の結果と、見つかったこと
別の評価担当（Opus）が、本物のホストと複数のスマホで実際に遊んで採点した。ババ抜きは15点（合格は16点以上・あと1点）、大富豪は18点（合格）。秘匿の漏れは0件。次の点を直す。

### ババ抜き
1. **番でも引かれる側でもない人（3人以上のとき）のスマホに、押せない灰色の「1〜6」だけが、説明なしで出る。** 開始時・つなぎ直した後・一時停止を解いた後に出る。`logic.js` の `padFor` の最後の `tiles`（`disabled:true` つき）。
2. **上がった人のスマホに「あなた：。1位」という崩れた文が出る。** 手札が空のとき、`あなた：` のあとが空になる。
3. **退出で終わったとき、残った人のスマホが古い画面（押せる「ひく」）のままだった**（評価担当の観察。原因は未確認）。`transition` の `ended` の分岐は、`feedback` の席にしか pad を送らない。
4. ジョーカーを引いても、「ひいた札：JK。」と、ほかの札と同じ文字だけ。
5. 結果の「記録」欄が、順位をくり返すだけ（label が `n位`）。退出した人には「退出」の印と、label「退出」が二重に出る。

### 大富豪
6. **出せる札が1枚もない番で「出す」を押すと、「同じ数を1〜4枚、場より強く出してください」と出て、パスへの案内がない。**
7. 結果で、退出した人に「（退出）」の印と、label「退出」が二重に出る。

## 直し方
- 1：第三者（`seat.id` が `from` でも `to` でもない席）には `wait` を出す。title は「{引く人}さんが{引かれる人}さんから札をひいています」（24文字以内に収める）、body は自分の手札。押せない `tiles` は出さない。引く人だけが `tiles`。
- 2：手札が空のときの手札の文を「あなた：札なし」にする。`feedback` の `body` の末尾の順位も、「。1位」でなく「1位で上がりました」の形にする。手札が空になりうる全部の文（`wait` の title・body）を見て、崩れる所が他にないか確かめる。
- 3：まず logic の試験で再現する（3人・1人が上がったあと、ジョーカーを持つ人が退出して、残る1人にジョーカーが渡り、その場で終わる）。`ended` に入るとき、`end` より前に、退出していない全席へ `wait`（title「勝負が終わりました」・body は自分の手札と順位）を送る。**`end` と同じ瞬間の pad はスマホに届く前に結果のリモコンへ置き換わることがある（docs/sdk.md）**ので、これは「古い画面を残さない」ためで、届かなくても害がないこと。原因が別なら、報告に書く。
- 4：ジョーカーを引いた本人の `wait` の title を「ジョーカーをひきました」にする（ほかの人には出さない。振動は今のまま）。
- 5：label を、上がった人は「{n}番目に上がり」、最後の人は「ジョーカーが残った」、未成立は「未成立」、退出した人は「記録なし」にする（12文字以内）。
- 6（大富豪）：出せる札が0枚のとき、`ok` の文字を「出せません」にする。`ids:[]` で `pass` なしの入力は、場があれば「出せる札がありません。パスしてください」、場がなければ「出す札を選んでください」と断る（今の「同じ数を1〜4枚…」にしない）。**断りの画面が毎回変わる仕組み（`refused`・token）は壊さない。**
- 7（大富豪）：退出した人の label を「記録なし」にする。

## 試験
- 上の1〜7を、`logic.test.js`（と画面の試験）で守る。それぞれ、直す前は赤・直した後に緑になることを、壊して確かめる（1か所を元の形に戻して赤を見る）。バグ修正の試験には「なぜ失敗したか」を書く。
- 秘匿の試験（他席の手札・ジョーカーの場所が出ない）が、新しい文でも通る。第三者の title に、引かれる人の手札の中身が入らないこと。
- 変異（`party-pack-*.json`）：「第三者に tiles を出す」「手札が空の文を直さない」「ended で最終画面を送らない」「出せる札0枚の断りの文を戻す」を足す。行が変わって既存の変異の `find` が見つからなくなったら、新しい行に合わせて直す。全部赤（killed）になること。
