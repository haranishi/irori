# 追補D4：人狼とボウリングの改善（実際に遊んだ評価担当の指摘・改善の1周目）（Codex）

`00-共通の約束.md` を先に読む。前回の報告（`reports/人狼の判定.md`・`reports/人狼の画面.md`・`reports/追補D2.md`）と、`.kiro/specs/party-game-pack/game-werewolf.md` も読み直す。

## 所有する場所
`games/moon-village/`・`games/strike-alley/`（画面・試験を含む）、`tools/mutations/specs/party-pack-moon-village.json`・`party-pack-strike-alley.json`、`reports/追補D4.md`。**`tests/e2e/` は触らない**（メインが持つ）。通信の型・ホスト・pad-ui も変えない。E2E が頼っていそうな文字（`・勝ち`・`・負け`・`退出`・`決定`・`投票する` など）や `publicView` の形を変えたら、`tests/e2e/console/party-pack.spec.ts` を grep して、影響する行を報告に書く。

## 評価の結果
別の評価担当（Opus）が、本物のホストと5台のスマホで実際に遊んで採点した。人狼は11点（合格は16点以上。「進行の信頼性」が0点）、ボウリングは19点（合格）。秘匿の漏れは0件。

## 見つかったこと（人狼）
1. **【高・メイン側で再現済み】決選投票が始まるとき、最後に投票（棄権）した席が、決選で投票も棄権もできなくなる。** 再現：4席で、席1→2・席2→3・席3→1 に投票し、席4が最後に棄権する。同数で決選が始まる（候補1・2・3）。席4の決選の画面は、1回目と同じ内容（候補1・2・3・同じ note・同じ token）で、`transition` が「前の画面と同じ」と判断して epoch を進めず、席4へ pad を送らない。ホストの送信係は前回と同じ内容を送らないので、席4のスマホは「送りました」のまま固まり、2分の上限まで動けない。原因は、`transition` が、画面の内容の比較だけで epoch（token）を進めるかを決めていること。
2. 投票の途中で1人の回線が切れる・夜に一時停止すると、決定が全員ぶん消えて選び直しになり、スマホに理由が出ない。`reconcile` が、中断の始まりで `picks` を空にしている。
3. 導入に、勝ち方・役の種類・人狼の人数が出ない（終了まで出ない）。
4. 役の確認の間、何人が確認し終えたかが大画面に出ない。
5. 昼になると、占い師は昨夜の占い結果を見直せない（夜明けの画面にだけ出て、昼は「大画面を見てください」）。
6. 夜に襲われた人のスマホには、自分が襲われたことが書かれない（占い師なら占い結果だけ）。
7. 結果で、占い師と騎士も「村人・負け」と書かれ、役が分からない。退出した人に「（退出）」の印と、label「退出」が二重に出る。
8. 導入の読み上げ文に「言葉を交わそう。。」と句点が2つ続く（`view.js` の `words` の `copy` に句点があり、どこかで句点をもう一度足している）。

## 見つかったこと（ボウリング）
9. 遊ぶ長さの選択ボタンが、語の途中で折り返す（「ふつう（10フ／レーム）」）。`logic.js` の `options` の label。

## 直し方
- 1：`transition(before,next,forceSeat)` で、**決める場面が新しくなるとき（`before.phase !== next.phase`・`before.runoff !== next.runoff`・`before.day !== next.day`）は、全席を `forceSeat` と同じ扱いにする**（epoch を進め、画面を必ず送る）。あわせて、**受理された入力のあと、入力した席の画面は必ず（JSON が）変わる**ことを、既存の無作為な対戦の試験（4〜8人×各500回）の性質として足す：送信係の「同じ内容は送らない」を真似て、席ごとに最後に送った JSON を覚え、受理された入力（状態が変わった入力）のあと、その席に前回と違う内容の pad が出るかを毎回確かめる（固まりの検出）。再現の例（上）も、独立した試験にする。
- 2：中断（一時停止・接続切れ・非表示）が始まっても、**夜と投票の「決定」（`picks`）は残す**（時計の `remaining` と、「役を見る」の表示 `showRole` は、今まで通り戻す）。再開後、全員の決定がそろっていれば、そのまま進む。仕様の要件5.2の「確定前の選択を捨て」は、決定前の選択のことで、決定済みの `picks` は対象でない、と読む（`.kiro/specs/party-game-pack/requirements.md` は触らない。報告に書く）。席が接続切れの間も、その席の決定は残る。接続切れの席の決定がそろっていないときは、今まで通り待つ。
- 3：`publicView` に、導入のときだけ、人数に応じた役の内訳（`roles.js` の `rolesFor` から、役ごとの人数。役の割り当てではなく人数だけ）を足し、導入の画面に「勝ち方：人狼を全員見つければ村の勝ち。人狼が村人と同じ数になれば人狼の勝ち」と「いまの人数の役：人狼1・占い師1・騎士1・村人2」を出す（5人の例）。導入以外では `null`。導入の場面は3幅（390・768・1440）で欠けないこと。**公開情報に足すので、`checkPrivacy` の `publicView` のキーの一覧と、秘匿の試験（役の割り当てが出ないこと）を更新する。**
- 4：`publicView` の `decided` を、役の確認（`reveal`）でも出す（確認し終えた人数 / 参加人数。誰がかは出さない）。大画面に「2 / 5人が確認」と出す。
- 5：占い師の席にだけ、昼の `wait` の body に、昨夜の占い結果（夜明けに見せたものと同じ文）を残す（次の夜の始まりで消す）。ほかの席・ほかの役は今まで通り「大画面を見てください」で、役が分かる情報を出さない（昼の画面は、全員の画面の形が同じ）。
- 6：夜に襲われた席（公開される情報）のスマホの夜明けの `body`（進行役なら `note`）の先頭に「あなたは襲われました。」を足す。
- 7：label を `{役名}（{村人側|人狼側}）・{勝ち|負け}` の形にする。例：「占い師（村人側）・負け」「人狼（人狼側）・勝ち」は長いので、人狼は「人狼・勝ち」、村人は「村人・勝ち」、狂人は「狂人（人狼側）・勝ち」、占い師・騎士は「占い師（村人側）・勝ち」の形。12文字以内。未配役（退出）の label は「記録なし」にする（今は「退出」で、印と二重になる）。`・勝ち`・`・負け` で終わる形は保つ（E2E が見る）。
- 8：句点が2つ続く原因を見つけて直す。他の文にも同じ重なりがないか grep で確かめる。
- 9（ボウリング）：選択肢の label を「10フレーム」「5フレーム」にする（折り返さない長さ）。長さが分かる説明は、画面の本文側に残す。

## 試験
- 1〜9 を、`logic.test.js`・`view.test.js` で守る。直す前は赤・直した後に緑を、壊して確かめる。バグ修正の試験には「なぜ失敗したか」を書く。
- 変異（`party-pack-*.json`）：「場面が新しくなっても epoch を進めない（1の原因）」「中断で picks を空にする」「導入の役の内訳に割り当てを入れる」「昼の wait に他席の役を入れる」「襲われた人の注記を外す」を足す。行が変わって既存の変異の `find` が見つからなくなったら、新しい行に合わせて直す。全部赤（killed）になること。
- 既存の無作為な対戦（4〜8人×各500回）・秘匿の走査・変異が全部通る。
