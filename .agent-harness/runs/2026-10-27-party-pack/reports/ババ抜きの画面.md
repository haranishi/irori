## ③ 壊して確かめた変異（2件とも検出。元に戻し、cmp で差分なし）

## 画面の観察と直したこと（3周）
- 1周目：扇の端の札が名前に重なる／線の矢じりが席の箱に隠れる／1440幅で札が小さい／ジョーカーが名前に重なる／配札中の見出しが「いまの番」／案内文が演出より先に次の番になる／ペアの2枚が重なり数字が隠れる。→ 扇の根元を上げ、線は箱の外だけに引き、文字は演出の終わりにそろえ、ペアは左右に並べてから返す。
- 2周目：低い画面の8人で席が接する／640×480の3人で上の席が捨て札を隠す／4人で名前が折り返し「ひく番」が上の席に掛かる。→ 札の大きさを「席と捨て札が重ならない最大」を探す方式にし、捨て札を空いた上下へずらす。
- 3周目：640×480の導入で規則3列が窮屈（1字だけの折り返し）→ 横に広い低い画面だけ3列。終わりの間を約6.8秒から約5秒へ。小さな文字を16px寄りに。

## ④ 設計への提案・未解決・規則の穴
- **退出でジョーカーの所在が漏れる（判定の担当へ）**：ジョーカーを持つ人が退出すると、残りの誰かの手札へ移る。その人の枚数が1増え、大画面とスマホの札の数に出るので、移った先が全員に分かる。画面側では枚数を偽れない。退出時に複数人の手札を1枚ずつ動かす、などの判定側の対策か、READMEでの明記が要る。
- **引いた人への個別通知は、次の手まで残る（判定の仕様）**：数秒で戻すには、改訂番号を変えずにその席だけ pad を出し直す時間イベントが判定に要る。menu などの擬似イベントで消すと全員の札の識別子が変わり、番の人の選択が消えるため、画面側では時間で消していない。最後の手の通知は、終わりの間（約5秒）のあいだ読める。
- 開始ボタンは `pad` の種類（スティックなし）を使う。`pads` に `pad` を足すと棚に「スティックか十字キー」と出るため、指示どおり入れていない。
- 大画面には押せる要素が無い（操作はスマホ）ので、キーボードの焦点の表示は対象外。
- 390幅は席を2列に並べる。隣が上下に詰まり線が隠れるので、線は出さない。誰が誰から引くかは、見出しと席の札（ひく番・ひかれています）と枠（実線・点線）で示す。
- 仮想プレイヤーのキー操作は、席をクリックしないと番号の小さい「見るだけ」の席が対象になることがある（SDK側の挙動。READMEに「番の人のパネルをクリックしてから」と書いた）。

## ⑤ 人が確かめるべきこと
- 実機のTV・ノートPCでの見え方（1080pでの文字と札の大きさ）、実ホスト＋スマホ3台の通し（秘匿・退出・復帰）。
- 効果音の時機と聞こえ方：`deal` は配り始め、`flip` は札が浮く瞬間、`place` はペアが捨て札に着く瞬間、`win` は順位の札が付く瞬間、`lose` はジョーカーを見せる瞬間に頼む（判定が返した依頼を演出に合わせて送るだけで、画面側で足していない）。ジョーカーを引いたときの振動。
- 演出の速さ（引く約0.6秒、ペア約1.2秒、終わりの間約5秒）が、遊びのテンポに合うか。

## 撮影の手順（棚の画像。tools/make-thumbs.mjs の SCENES へ）
人数は既定の3人。640×480で、上に1席・下に2席、捨て札は下へずれ、1→2の線と矢じりが見える（手元で同じ手順を真似て撮ると48KB）。
```js
'old-maid': async (page) => {
  await phase(page, 'intro');
  await page.keyboard.press('Space'); // 進行役（仮想プレイヤー1）の「はじめる」
  await phase(page, 'play');
  await page.waitForFunction(() => !document.getElementById('stage')?.hasAttribute('data-busy'), null, { timeout: 15_000 }); // 配札の演出の終わり
  await page.waitForTimeout(600); // 線が伸び切るまで
},
```
