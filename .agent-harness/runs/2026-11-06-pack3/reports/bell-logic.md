# 担当A：bell-logic

## 実装
- 配札・5つの効果・同時選択・時計・一時停止・切断時のおまかせ・退出時の終了を純粋な判定に実装。
- 乱数は保存できる種つき。初周に出せる札が最低1枚になるよう、配札後に種類を交換する（構成枚数は変更なし）。
- 公開状態には枚数・出した札・出来事だけを載せる。秘密の結果は本人のpadに3秒表示し、本人用の記録に保持する。
- CPUは本人用の情報だけから推理し、移動より前の証拠を失効させる。確認済みの鈴には確実に指名する。
- 結果には全席の得点・同順位・CPUの印があり、通常終了のendは結果公開から8秒後の1回だけ。

## 担当Bへの引き継ぎ
- `createGame(init)` / `updateGame(state,event)` は `{state,effects}`。型は各ファイルのJSDocにある。
- init：`players`・`leader`・`seed`・`nonce`（小文字英数1〜8字）、`environment:{connected,visible}`・`paused`。
- 人の席IDは数値。CPUは `fillSeats(h)` の `cpu1` …。補充は局の最初に行い、playersへ結合する（人3人以上なら追加なし）。
- イベント：`input:{p,input}`、`tick:{ms}`、`players:{players,leader}`、`menu:{paused}`、`environment:{value}`（いずれも `t` が種類）。
- `tick.ms` は既存ゲームと同じ経過ミリ秒。時計の実装はmainに置き、取得した差分だけ渡す。判定側は実時計を読まない。
- 一時停止・ホスト切断・非表示ではtickを消費しない。停止中の差分を再開後へ持ち越さない。席の切断は時計を止めない。
- `publicView(state)` だけを大画面へ渡す。生のstate・viewForは描画や全員宛て通信へ渡さない。
- 公開の `seats` はID・名前・枚数・守り・接続・出した回数・CPU等。`discard`、連番つき`events`、`turn`、`step`、`remaining`も返す。
- `holder` は結果で成立した局だけ公開。`results` に全席のscore・rank・cpu、`clear` は移動で失効していない外れ指名先。
- 公開イベント：`play`・`peek`・`swap`・`whisper`・`guard`・`miss`・`caught`・`auto`・`skip`・`noTarget`。`auto` は「おまかせ」と表示する。
- `viewFor(state,p)` は公開情報＋自分の `hand`・`observations`・`notice`・`pad`。複製を返す。他席の手札・伏せ札の対応は含まない。
- `pad`効果は必ず`to`宛て。`wait`と`tiles`だけ。識別子は不透明な位置ID。入力は`{k:'tiles',ids:[tile.id],t:pad.token}`。
- padとtokenは判定が作るのでmainで組み直さない。拒否は本人のtokenだけ進む。同時選択では未回答者のtokenを保つ。
- CPUごとに保存した種つき乱数を使う。`thinkMs(rng)`後に最新の`viewFor`を取り、`decide(view,id,rng)`が返した入力を通常のinputイベントで渡す。
- `decide`がnullなら待つ。シーン変更・停止時は保留中のCPUタイマーを取り消して再予約する。試験では思考時間を省略した。
- `end.results` はCPU込み。コンソールへは`typeof result.p === 'number'`で人だけを渡す。pad・vibrateも人のIDだけSDKへ転送する。
- 途中参加者の新規席はこの判定で追加しない。次の局のcreateGameで名簿と補充を決め直す。
