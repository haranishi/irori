## 実装
- SDKへinitの名簿・リーダー・種・識別子・環境を渡し、input・players・pause/resume・environmentを判定へ接続。
- tickには経過ミリ秒だけを渡す。停止・切断・非表示の時間は持ち越さない。
- pad・振動・endは人の席だけへ。大画面へ渡すのはpublicViewだけ。
- 人が3人未満なら5席までCPUを補充。思考後の最新viewForでdecideし、通常のinputで渡す。
- CPUの予約はtokenと場面に対応し、停止・場面変更・pagehideで破棄。demoは人0席で結果8秒後に次局へ進む。
- 深い藍・墨・朱・金の屋台、席の輪、伏せ札、公開の山、直近4件、時間の輪、守り・外れ指名・CPUの印を描画。
- 成立した結果だけ鈴・猫・全席の得点を表示。文字はtextContent、札と印はCSS・自作SVG、動きを減らす設定と停止を反映。
- READMEは48行。札・規則・人数・CPU・得点・権利を記載。

## ブラウザと開発サーバーの制限
- 指定どおり `IRORI_DEV_PORT=8830 npm run dev` をバックグラウンドで起動。8787など他担当のポートには触っていない。
- サーバーは健康確認に応答したが、新ゲームのURLは404。prepare:web・Web明示ビルド後も404のまま。
- 上記のブラウザ確認は9333の既存サーバーへconnectし、自分専用contextで、8830のゲームへの要求だけを最新の所有ファイルでroute.fulfillして行った。
- contextはすべて閉じた。実ブラウザの描画・入力・CPU・再戦は確認したが、通常の静的配信経由での確認とは区別する。
- 起動PIDは18712。プロセスグループとPIDへのSIGTERMはどちらもEPERMで拒否された。メインへ停止を依頼済み。停止済みとは報告しない。
- サーバー起動ログ・PID：`.probe-tmp/bell-ui-dev.log`・`.probe-tmp/bell-ui-dev.pid`。
