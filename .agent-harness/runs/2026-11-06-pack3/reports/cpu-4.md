# cpu-4：既存7ゲームのコンソール結果

## 変更

- 開始時に固定したCPUのID集合を使い、終了送信前に人の行だけへ絞る。
- CPU入りの局は `ranked:false` と4項目だけを送る。人だけの局は元の行を維持する。
- ゲーム自身の結果画面はCPUを含むまま。未成立・退出の記録は順位へ置き換えない。

| ゲーム | CPU入りのlabel |
|---|---|
| old-maid | 全席の確定スコアから `N位(CPUこみ)` |
| daifugo | 既存の階級（大富豪〜大貧民） |
| tap-race | 判定のstandingsから `N位(CPUこみ)`。0点同士でも得点から推測しない |
| ten-seconds | 累計ズレのスコアから `N位(CPUこみ)`。最終回の順位は使わない |
| lantern-market | 全席の合計点から `N位(CPUこみ)`。同点は同順位 |
| blade-duel | 既存の体力 |
| moon-village | 既存の役と勝ち負け |

- 上記7ゲームの `main.js`・`logic.js`・`cpu-main.test.js`。

## 検証

- `nice -n 10 npx vitest run --config vitest.games.config.ts`（対象7ディレクトリ・`--maxWorkers=1`）：28ファイル・696件成功。初回のモック不足4件を修正して再実行。
- 各ゲームのmain通し：7ファイル・24件成功。CPU入りの4項目・非順位・labelと、人だけの終了行不変を確認。
- `cd packages/protocol && nice -n 10 npx vitest run`：9ファイル・306件成功。
- 契約試験単独：7件成功。全7ゲームの `ranked:false` を一時的にtrueへ変更すると7件すべて失敗。
- 変異後は元へ復元し、全7ファイルのSHA-256一致を確認。証拠：`.probe-tmp/cpu-4/hashes.json`。
- `nice -n 10 npm run typecheck:games`：成功。
- `nice -n 10 npm run check`：初回全項目成功。再実行は担当外の一時生成物で2項目失敗（下記）。
- `git diff --check`（所有する場所のみ）：成功。
- niceの優先度設定は環境から拒否されたが、指定した各コマンド自体は実行された。

## 実ホストのブラウザ確認

- 接続サーバーのChromiumで、ホストとスマホを別文脈にし、通常の `/` →参加→ゲーム選択から終了。
- ババ抜き：人1＋CPU3、コンソールは「—／2位(CPUこみ)」。余分な1位なし。
- 大富豪：人1＋CPU3、コンソールは「—／大貧民」。余分な1位なし。
- 画像を実際に開いて確認。`.probe-tmp/cpu-4/old-maid-console.png`・`daifugo-console.png`。
- 開始時に一度 `/pad` が500を返した。再度の通常配信で参加・終了に成功。
- 大富豪の自動操作は複数枚を要求する場で単札が拒否されたため、パスを優先する操作へ直して終了。
