# 要件：検証済みのmainを自動公開する

保守者がCloudflareへの公開を手作業で繰り返さずに済むよう、既存CIの成功を条件にCDを追加する。本人承認済み。

## 対象と前提

- 対象はCDの設定、公開前の検証コマンド、導入・停止・復旧の運用文書。
- 現在のビルド、Workerと静的ファイルの一体配信、部屋の保存方式を引き継ぐ。
- ゲーム・画面・通信、依存更新、独自ドメイン、PR用プレビューは今回の対象外。
- push・外部設定の変更・初回公開は、本人からその操作の明示指示を受けた範囲で行う。

## 1. mainの検証成功を公開条件にする

保守者は、既存の検証を通った変更だけを公開できる。

- 1.1 When mainへのpushに対する既存CI全体が成功し、保守者がCDを有効にしている, the irori CD shall 検証されたコミットを公開対象にする。
- 1.2 If CIが失敗・中断された、またはPR・定期実行・手動実行によるCIである, the irori CD shall 自動公開を行わない。
- 1.3 If 公開直前の確認で対象コミットがmainの先頭から外れている, the irori CD shall そのコミットの公開を省略する。
- 1.4 While 別の公開処理が実行中である, the irori CD shall 公開処理を同時実行せず、進行中の公開を後続の変更で中断しない。

## 2. 認証と有効化を運用者が管理する

保守者は、認証情報を公開せずにCDを有効化・停止できる。

- 2.1 While CDが未設定または無効である, the irori CD shall 公開を省略し、既存CIの成功判定を妨げない。
- 2.2 If CDが有効なのに公開用の認証情報が足りない, the irori CD shall 不足する設定名を示して公開前に失敗する。
- 2.3 The irori CD shall 認証情報を保護された設定から受け取り、その値をリポジトリやログに記録しない。
- 2.4 The irori CD shall 公開用の認証情報を、依存の導入とビルドの処理に渡さない。

## 3. 公開する構成を事前に確かめる

保守者は、公開先を変更せずにWorkerと静的ファイルを検証できる。

- 3.1 When 公開前の検証コマンドを実行する, the irori 開発ツール shall 最新のソースから配信物を作成し、外部へ公開せずにWorkerのバンドルを検証する。
- 3.2 If ビルドまたは公開前の検証が失敗する, the irori CD shall 公開しない。
- 3.3 The irori CI shall 既存の検証を維持し、公開前のWorkerバンドル検証も実行する。

## 4. 初期設定と復旧の手順をまとめる

保守者は、必要な設定、停止方法、失敗時の対応を運用文書から確認できる。

- 4.1 The irori 運用文書 shall 必要な設定名と登録先、有効化・停止、CI成功から公開までの条件、再実行と復旧の手順を示す。
- 4.2 The irori 運用文書 shall デプロイ時の接続切断と、部屋の保存に関する既存の注意を参照できるようにする。
- 4.3 The irori 導入記録 shall ローカル検証、GitHubでの実行、初回公開の実施状況を区別して記録する。
