# 共通の約束：CPUの席（1人や人数不足でも試せるようにする）

要件 5。2026-11-06 の本人の依頼（音声入力）。「1人のときや、人数が足りないときは CPU を加えて。そうしないと試せない」。第2弾で範囲外にした「CPUの参加者」を、第3弾で範囲に入れる。

## 方針
- プラットフォーム（SDK・中継・コンソール）は変えない。CPU は各ゲームの中で動かす。人の席が足りないとき、ゲームが内部の席（`cpu1` …）を足す。
- コンソールは CPU を知らない。名簿・結果のリモコン・一時停止メニュー・`end` の記録は、人の席だけ。ゲーム自身の結果の画面には、CPU も載せる。
- 登録情報の `players.min` は、人の最小人数（1）にする。足りない分は CPU が埋める。ゲームの説明に「1人でも CPU と遊べる」と書く。

## 補充の規則
- 人の数 h が、そのゲームの最小人数 m より少ないときだけ、合計が推奨人数 r になるまで CPU を足す。h が m 以上のときは足さない（集まった人で遊ぶ）。
- r は各ゲームの README に書く。CPU の名前は「CPU 1」…（12文字以内）。席の印は、人の席と区別できる記号（ロボット風の図形）を付ける。
- 途中で人が増減しても、その局の間は補充を変えない。次の局の開始で決め直す。

## コンソールの結果の扱い（2026-11-06 の採点で見つかった食い違い）
- コンソールは、人の席だけで順位をつける。人1人＋CPUでは、ゲーム内で3位でも、コンソールの結果は「1位」と出て食い違う。
- CPU が入った局では、`end` の人の席の行を `ranked: false` にし、`label` に、CPU を含むゲーム内の順位を「N位(CPUこみ)」の形で入れる（12文字以内。役や勝ち負けが意味を持つゲームは、その言葉に「CPUこみ」を添えるか、そのまま）。コンソールは、`ranked:false` の行に順位を付けない。CPU が入っていない局は、従来どおり（`ranked: true`）。
- 行は、人の席だけ・`p`・`score`・`label`・`ranked` の4項目だけ（SDK の検証）。ゲーム自身の結果の画面には、CPU を含む順位を出し続ける。

## CPU の頭（ゲームごとの `cpu.js`）
- 純粋な関数 `decide(view, seat, rng)`。人のスマホが送る入力と同じ形の入力を返す。`view` は、その席が人なら見られる情報だけ（自分の手札・公開の記録・自分が得た結果）。他席の手札や役といった隠れた情報は読まない。試験で、`view` に隠れた情報が無いことを守る。
- 強さは「ふつう」。合法手の中から、手がかりに基づく重みつき乱数で選ぶ。人が勝って当然にも、負けて当然にもしない。勝率は自動対戦で記録する。
- 考える時間は0.8〜2.0秒（種つき乱数）。試験では0にできる。同時に選ぶ段階では、CPU ごとに時間をずらす。
- 乱数は種つき。同じ種と同じ入力から、同じ結果になる。

## 試験
- `decide` が、全段階で常に合法手を返す（人数ごとに2000局）。人だけの局と、人1＋CPU の局が、必ず終わる。
- `view` に隠れた情報が無い。CPU だけの局（デモ）が、人の入力なしで最後まで進む。
- 実ブラウザ：1人＋CPU で、開始から結果まで通る。結果の画面に CPU が出る。
