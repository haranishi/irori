# 既存ゲームへCPUの席を足す

CPUはゲームの中だけに置く。コンソールの名簿・スマホ・結果の記録には追加しない。
人が足りないときも、進行役の「はじめる」から通常の手順で遊ぶ。

## 席と補充

- `fillSeats(humans)` は追加する席だけを返す。人数は整数の0〜8。人が元の最小人数m未満なら推奨人数rまで補い、m以上なら空の配列。
- ババ抜きはm=2・r=4、大富豪はm=3・r=4。登録の `players.min` は人の人数なので1。
- 人の席IDはSDKの正の数値。CPUの名前は `CPU 1` …、`cpu:true`、`online:true`。通常は負の数値IDを使う。
- ババ抜きは `fillSeats(humans,rng)` で人より前のCPUの数を種つきで等確率に選ぶ。後ろのCPUには大きな正IDを使い、最初の番も数値順の先頭から選ぶ。IDの符号だけでCPUを判定しない。
- CPUの一覧は局の作成時に固定する。名簿更新にも同じCPUを結合し、途中の増減で補充し直さない。次の局で決め直す。
- CPUのIDは判定と画面だけで使う。SDKの `look` にも渡さず、専用の灰白色のロボット図形を描く。

## 頭に渡す情報

- `logic.js` の `viewFor(state,seat)` は公開モデル＋本人の手札＋本人用padだけを複製する。他席の手札、乱数状態、山札、伏せ札との対応を含めない。
- `cpu.js` の `decide(view,seat,rng)` は本人用ビューだけから、通常の入力と同じ形を返す。選べない段階は `null`。
- `view.self` と席が違えば拒否する。本人用padのtokenと札IDをそのまま使い、古い入力を組み直して送らない。
- `rng` は呼び出し側が保持する種つき乱数。決定と `thinkMs(rng)` に実時計や `Math.random` を使わない。
- 思考時間は800〜2000ms。ババ抜きは伏せた札の位置を無作為に選ぶ。
- 大富豪は既存の合法手列挙を再利用し、場に合う弱い札から選ぶ。同じ強さは乱数。8切り・革命は序盤に温存し、終盤や他に手がないときに使う。出せなければ場があるときだけパスする。

## mainのドライバー

1. `players` とCPUを結合して `createGame` と名簿イベントへ渡す。
2. CPUごとに乱数の列を持つ。操作できるpadがある席だけ `thinkMs` 後の予約を作る。
3. 発火時に最新の `viewFor` を取り直して `decide` し、通常の `input` イベントへ渡す。
4. 状態の変更では古い予約を全て取り消して再予約する。停止・切断・非表示のpadは操作不可なので予約しない。
5. 終了・ページ破棄でも予約を取り消す。画面の演出用時計とCPUの思考時間は別に管理する。
6. `pad`・`vibrate`・`end.results` は人だけに絞ってSDKへ渡す。画面にはCPUを含む公開モデルを渡す。

## 試験

- 元の最小人数〜8席を各2000局、全段階の合法手と終了を検査する。
- 人1＋CPUを2000局、CPUだけを2000局、人だけの局、同じ種の結果を検査する。
- 他席の秘密を同じ枚数の別の札へ交換しても、本人用ビューが変わらないことを検査する。ビューの変更がstateへ戻らないことも検査する。
- 停止中・番以外・終了後の `null`、思考時間の上下限、予約の取消し・最新ビューの再取得を検査する。
- mainを実際の判定へ接続し、再開から結果まで進める。SDKにCPUのIDや記録が届かず、結果の画面にはCPUが残ることを検査する。
- ブラウザでは `?mock=1` の開始〜結果と、人数充足時の補充なしを確認する。画像だけで進行成功とは判断しない。

## 見つかった落とし穴

- 数値を前提にする判定へ文字列IDを混ぜると、席順と次の番が壊れる。
- 名簿イベントへ人だけを渡すと、判定がCPUの退出として扱う。
- 古いpadから入力を作るとtokenが合わない。発火直前に取り直す。
- CPUへpadを送らないだけでは足りない。番・革命・上がりの振動をmainで作るゲームも、宛先を人に絞る。
- SDKの結果にはCPUを載せないため、ゲーム自身の結果表示を残す必要がある。
- 登録の英語summaryは80文字まで。CPUの説明は既存文を短くして収める。
- 数値順と「0より後」の開始位置が重なると、人だけ同じ位置から始まる。ババ抜きは2000局で人の1位が13.95%→25.20%。大富豪は23.65%で偏りが小さく、変更なし。
- 大きな正IDへ乱数の定数を掛けると整数精度を失う。席ごとの乱数列は32bitへ分けて混ぜる。

## 同時進行・時間を数えるCPU

- 連打レース・せーので10秒・灯市のかけひきはm=2・r=4。人が2人いればCPUなし。
- 連打は `decide` が1押下、`createPace(rng).nextMs(rng)` が次の間隔。席の平均95〜140msを固定し、1打ごとに±30%揺らす。合図前・完走後は操作しない。
- 10秒は `createTiming(rng)` で早め・遅めの偏りを席に保持する。12個の一様乱数の和で標準偏差350msのずれを作り、0〜20秒に収めて1回だけ押す。
- 時間型のdriverはゲーム時計を受け取り、padが変わったときだけ予定を作る。毎フレーム予定を引き直すと永久に押せない。停止は時計を止め、やり直しは予定を捨てる。
- 灯市は本人の手札と公開済みの使用札だけを見る。中〜高の札と、相手に残る枚数が少ない札を重くし、確率で選ぶ。他席の仮選択は見せない。
- 同時選択の予約は席ごとのpadで保持する。他席の回答のたびに全予約を消すと、遅いCPUが先延ばしになる。
- 連打でサーバーのTとCPUのローカル時刻を混ぜると時計のずれが順位になる。CPU入りの局は全席を停止可能なゲーム時計で比較し、人だけの局は従来どおりTで比較する。
- SDKの結果からCPUを除くゲームは、自分の結果画面に全席の順位・得点を残す。同率1位があるゲームの勝率は、同率の件数と人数で分けた値を併記する。

## 同時対戦と秘密の役

- チャンバラはm=2・r=2。本人用ビューは公開体力・気力・確定済みの手の履歴と本人のpadだけ。他席の選択中の手は含めない。
- 合法な手から重みつきで選ぶ。相手の気力0なら斬る、直前が受けるなら溜めるを重めにし、大技でも固定しない。
- 人狼はm=4・r=6。既存の正ID検査を保つためCPUも正の内部ID。固定CPU一覧で識別し、符号を判定に使わない。
- 人狼の本人用ビューに入れる秘密は本人の役・騎士の前夜の護衛先・本人が得た占い結果・本人が人狼のときの仲間だけ。公開票と死亡は公開モデルから読む。
- 占い結果は夜を越えて本人用履歴に残す。対象IDと結果だけを記録し、他席の役の一覧や未確定の夜行動・投票を渡さない。
- 人狼は仲間を襲わず、占い師は未確認を優先し、騎士は連続護衛を避ける。昼の議論では発言しない。人の進行役が投票へ進められる。
- 同時選択のdriverは本人padを予約キーにし、他席の回答では延期しない。発火直前にも最新padとの一致を確かめ、回復で無効になった入力は捨てる。
- 配役はCPUの印を見る前と同じシャッフル。人1＋CPUと人だけの各席を同じ方針・各2000局で比較し、引き分けと役の配分も数える。
- SDKのendへ渡す行は人だけ、p・score・label・rankedの4項目だけ。ゲーム自身の結果にはCPUも残す。

## コンソールへ渡す結果

- 局の開始時に固定したCPUの集合が空でなければ、人の行を `ranked:false` にする。人だけで順位を付けるコンソールとの食い違いを防ぐ。人だけの局の行は変えない。
- 順位のlabelは `N位(CPUこみ)`（12文字以内）。大富豪の階級・対戦の体力・村の役と勝敗は、その言葉を残す。未成立・退出の記録も順位へ置き換えない。
- 順位はCPUを除く前に決める。連打は得点だけでは0回と棄権が同点になるため、判定の順位を使う。10秒は最終回ではなく累計ズレを使う。
- 行は `p`・`score`・`label`・`ranked` の4項目だけ。CPUの集合で人を絞り、IDの符号で判断しない。
