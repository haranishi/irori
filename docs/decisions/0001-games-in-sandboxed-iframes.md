# ADR 0001：ゲームは隔離した枠（iframe）の中で動かす

状態：採用（2026-10-16）

## 背景

第三者が作ったゲームが、ホストの画面で動く。その画面は、部屋の鍵と通信路を持っている。もしゲームのコードを同じページに置けば、鍵を読まれ、画面を覆われ、通信に割り込まれる。置き場所を分けるしかない。

## 決めたこと

ゲームは、枠に閉じ込める。

- `sandbox` つきの `iframe` に入れる。許可は `allow-scripts` を基本とし、ポップアップ・画面遷移・フォーム送信・ダイアログは許さない。`allow` 属性は `autoplay` だけを渡す（ホストの画面でのクリックやキー操作を、枠の中の音の再生に引き継ぐため）。カメラ・マイク・位置情報などは渡さない。
- ゲームとコンソールの会話は、最初の握手のあと `MessagePort` の上だけで行う。親は `event.source` が自分の枠か確かめる。
- 同梱のゲームには `allow-same-origin` を付けない。オリジンが空になるので、`/games/*` とSDKにCORSを許すヘッダーを付けて配る。
- 外部のゲームは、コンソールと別のオリジンでだけ `allow-same-origin` を付けて動かす。自分のオリジンのストレージとネットワークは使える。コンソールと同じオリジンのURLは拒否する。

## 捨てた案

- **同じページに読み込む**：鍵と画面を握られる。
- **Web WorkerとOffscreenCanvas**：DOMと、既存のWebGLゲームがそのままでは動かない。
- **ゲームを別タブで開く**：大画面での操作と戻る導線が崩れ、ポップアップとして止められることもある。
- **外部のゲームも、オリジンを空にする**：配信元がCORSのヘッダーを返さないとモジュールの読み込みに失敗することがあり、制作者に余計な設定を求めてしまう。

## 代償と、見直す条件

外部のゲームは、自分のサーバーへ通信できる。止める手段はなく、審査と、開く前のホスト名の表示で補う。`credentialless` な枠のような標準が広く使えるようになったら、通信を絞れないか見直す。
