# ADR 0002：通信はWebSocketの中継から始め、WebRTCは実測してから足す

状態：採用（2026-10-16）

## 背景

流れるのは、数十バイトの入力が毎秒数十個。最大8人。サーバーに置きたいのは、部屋の管理だけ。

## 決めたこと

Cloudflare Workers の Durable Object に部屋を置き、WebSocketで中継する。フレームの型と、`packages/room` の「入力を受けて、やることの一覧を返す」という境界は守る。経路は、あとから足せる。WebRTCのデータチャネルを、同じフレームを運ぶ別の道として加えればよい。

## 捨てた案

- **WebRTCを先に作る**：STUNとTURNの運用が要り、学校や職場の回線では直接つながらない経路を、最初から抱える。つながらなかったときの逃げ道として、結局この中継が要る。先に作るべきは、必ずつながるほうだと判断した。
- **ロングポーリングやSSE**：双方向でなく、入力の遅延が大きい。
- **外部のリアルタイム基盤を使う**：サービスへの依存と、その料金体系が、自己ホストの入口を狭める。

## 代償と、見直す条件

同じ部屋の中でも、一度クラウドを往復する。遅延が体感に響くかどうかは、実機での測定がまだない。測るまでは「問題ない」と書かない。

実機で、入力から画面に反映されるまでの中央値が100msを超え、遊びの邪魔になるなら、WebRTCを足す。Cloudflareのアカウントが要るが、`wrangler dev` を使えば手元でも動く。
