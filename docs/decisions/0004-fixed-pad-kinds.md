# ADR 0004：スマホの画面は定型6種にし、自由なHTMLは持ち込ませない

状態：採用（2026-10-16）

## 背景

スマホの画面は、手に持つ道具であり、ゲームごとに作らせると壊れ方も増える。iOSのセンサー許可、画面の消灯、再接続、横向きの案内、読み上げは、どれも地味に難しい。

## 決めたこと

ゲームは、`wait` `pad` `buzzer` `choices` `touch` `tilt` の6種から選び、文字と色の名前だけを指定する。描画と入力の取り出しは `pad-ui` が持つ。席の色と形、メニュー、再接続の帯は、ゲームから触れない。

## 捨てた案

- **ゲームがコントローラー用のHTMLを持つ**：作れるものは増えるが、スマホ側でも第三者のコードが動き、隔離と許可と再接続を各ゲームが背負う。
- **JSONで座標まで指定できる自由なレイアウト**：画面サイズごとの崩れ、押しにくい配置、読み上げの順序を、ゲームごとに検査する必要が出る。
- **種類を最初から20種にする**：使われる前に保守の負担が増える。

## 代償と、見直す条件

定型で表せない遊びがある。表せない実例が3件集まったら、7種目を足すか、自由なHTMLの枠を作るかを、そのとき決める。7種目の判断では、既存の種類の組み合わせで足りないかを先に見る。

7種目は ADR 0009。
