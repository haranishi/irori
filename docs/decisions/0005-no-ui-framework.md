# ADR 0005：UIフレームワークを使わず、TypeScriptと標準のDOMで書く

状態：採用（2026-10-16）

## 背景

画面は、ホストが5つ（棚・詳細・ゲーム中・結果・メニュー）、スマホが4つ（参加・待機・操作・切断）しかない。動かす先は、ノートPCやTVのブラウザで、古い端末もありうる。外から取り込む依存は、更新と供給元の確認という保守の仕事を増やす。

## 決めたこと

状態の管理は小さな状態機械で書き、DOMは `h()` という数十行の補助で組む。描画した文字列は `textContent` で入れる。ビルドは Vite。コンソールのJSは、gzipで80KB以内、スマホの画面は40KB以内を目安にして、ビルドの後に容量を測る。

## 捨てた案

- **React・Preact・Lit**：宣言的に書ける利点はある。ただ、画面が9つで状態も小さいので、得より、読み込みの重さと更新の負担が上回ると判断した。
- **ビルドなしの素のJS**：型がなく、プロトコルの型をホスト・スマホ・Workerで共有できない。

## 代償と、見直す条件

画面の更新漏れを、自分の書き方で防ぐ必要がある。そのため、状態の変化は1つの関数から画面へ流す。画面が15を超えるか、更新漏れの不具合が続けて見つかったら、部品化の仕組みを足す。そのときも、フレームワークの導入は最後に検討する。
