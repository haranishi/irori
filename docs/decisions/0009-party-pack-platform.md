# ADR 0009：札と投票のための `tiles` を足し、効果音はコンソールが鳴らす

状態：採用（2026-10-27）

## 背景

ボウリング・大富豪・ババ抜き・人狼を足す（`.kiro/specs/party-game-pack/`）と、定型6種では出せない画面が3件そろった。大富豪は手札（3人なら18枚）から1〜4枚を選んで出す。ババ抜きは相手の最大13枚から位置を選ぶ。人狼は最大7人から1人を選んで投票する。`choices` は2〜6個・12文字までで、選べるのは1つだけ。ADR 0004 の「表せない実例が3件集まったら7種目を足す。先に既存の組み合わせで足りないかを見る」の条件に当たる。

あわせて、同梱のゲームは音を出していない。ゲームの枠はオリジンが空で、ブラウザの自動再生の制限に当たりやすい。コンソールの消音の設定は、ゲームには届いていない。

## 決めたこと

- **`tiles` を7種目にする。** 札や人を最大20個並べ、`min`〜`max`（最大8）個を選んで「決定」する。入力は決定かパスの1回だけ。能力 `pad-tiles-v1` で守る。`choices` は広げない。
- **効果音は、ゲームが決まった名前で頼み、コンソールが自前の合成音で鳴らす（`cue-v1`）。** 名前は固定の23個。消音と自動再生の解除は、コンソールの1か所で扱う。音声ファイルは足さない。
- **SDK の生の上限を60,000→72,000バイトにする。** gzip の上限（60KB）は変えない。

## 捨てた案

- **`choices` を20個・複数選択に広げる**：旧ホストが新しい値を受け取り、意味も重くなる。`tiles` を別の種類にすれば、能力の有無で守れる。
- **`choices` をページ送りで使う**：変更は要らないが、13枚の手札では操作が煩雑で、複数選択ができない。
- **ゲームが自分で音を鳴らす**：自動再生の制限に当たり、各ゲームに合成音のコードが重複し、消音も届かない。
- **SDK の整形を詰めて60KBに収める／仮想プレイヤーを別ファイルにする**：読める形のまま1ファイルで配る約束（docs/architecture.md、`packages/sdk/vite.config.ts`）に反する。

## 代償と、見直す条件

- 種類が7つになり、旧ホストでは `tiles` を使うゲームが動かない（更新の案内を出す）。`cue` の名前の一覧は固定なので、足すときはコンソールの合成と試験も足す。
- SDK は10〜12KB（約20%）大きくなる見込み。gzipは約18KBで、上限の30%に収まっている（実測は仕様の検証記録に残す）。実測が72,000バイトを超えたら、機能を削る前に人へ返す。
- 8種目を足したくなったら、`tiles` の拡張で足りないかを先に見る。傾きでの投球など、実機の検証が要る入力は、別の決定で扱う。
