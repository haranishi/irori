# 参考にしたサービスからは、仕組みと体験の型だけを借りる

着想の元になったWebサイトには、利用規約もライセンスも見つからなかった。権利は、すべて留保されているものとして扱う。調べた事実は [`.agent-harness/runs/2026-10-16-bootstrap/research/legal-facts.md`](../../.agent-harness/runs/2026-10-16-bootstrap/research/legal-facts.md)（出典の条文・判決つき）にある。これは法的助言ではなく、弁護士の確認も受けていない。

## 線の引き方

| 区分 | 具体例 | 根拠（要点） |
|---|---|---|
| 借りてよい | 一覧から選ぶ、QRで参加する、スマホを操作盤にする、傾きセンサーを使う、カードを並べる構成 | 著作権が守るのは表現で、アイデアや仕組みは守られない（著作権法2条1項1号、最判平成13年6月28日）。ありふれた画面構成が同じでも、複製や翻案にならない（東京地判平成14年9月5日、知財高判平成24年8月8日） |
| 借りない | コード、画像、音、文章、アイコン、配色の組合せ、動き、書体、利用規約の文面 | 規約の丸写しを複製権の侵害とした例がある（東京地判平成26年7月30日）。画面は全体の創作的な特徴が守られうる |
| 避ける | 他社の名称（任天堂の商標など）を、名前・ロゴ・ドメイン・画面の見出し・宣伝の中心に入れること。提携を匂わせること | 商標権・意匠権・特許権は、「写していない」でも侵害になりうる。名前に入れると、出所を示す使い方になりやすい（商標法25条・26条1項6号、知財高判令和2年1月29日） |

README などで、着想の経緯を一文で書くのは、記述的な使い方に近い。ただし中心には置かない。このリポジトリは、名前・ロゴ・画面・宣伝のどこにも、他社の名称を使っていない。

## このプロジェクトのやり方

1. **観察の記録は事実だけ**。何をしたら何が起きたかを、日付と方法つきで [`docs/research/`](../research/) に書く。コードの書き方や構造は書かない。
2. **実装する人には、参考サイトを見せない。** 実装担当には、自作の設計文書だけを渡した。参考サイトのコードを開いた人と、書く人は別にする。
3. **公開コードの確認は、設計者だけが、通信方式の種類を知る範囲で行う。** 調べたのは、使っている技術の名前（WebSocket、WebRTC、傾きセンサー）の有無と、その周辺の数行。写さず、メモにも書き写さない。
4. **設計の由来を残す。** 通信の型、部屋の規則、SDK、登録の仕組みは、自分の設計文書（`docs/`）から作った。
5. **機械の門番を置く。** `tools/check-rights.mjs` が、他社の名称、参考サイトの識別子、音声と書体のファイル、外部ドメインからの読み込み、私的なパスを拒む。外すと試験が赤くなることも確かめている。

## 貢献する人へ

他のサービスやゲーム機の画面を再現するPRは、受け付けません。参考にしたものがあれば、PRの説明に、何を参考にして、何を取り込んでいないかを書いてください。

## 権利者から連絡を受けたとき

[SECURITY.md](../../SECURITY.md) の非公開の窓口で受けます。まず、申出人が権利者か、侵害にあたるかを確かめる。そのうえで、目安として7日以内に、取り下げか修正かを決めて返します。GitHubにも、権利者が使える独自の手続（DMCAの通知）があり、リポジトリごと止まることもあります。窓口に届かなかった申立ては、人づての連絡でもよいので、Issueではなく非公開で知らせてください。

## 確かめていないこと

任天堂の商標・意匠・特許の登録状況は、取得できず、確かめていない（[rights-check.md](rights-check.md)に宿題として残した）。参考サイトの画面が、不正競争防止法の「商品の形態」に当たるかも不明。画面は、視覚の面で別のものにしたが、類似の判断は事案ごとに決まる。
