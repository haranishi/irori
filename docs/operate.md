# 動かし方と費用：無料プランの「止まる」を上限に使い、有料にしたら自分で見張る

3つの動かし方がある。どれもNode 24以上が要る。公開デモのデプロイは、保守者はまだしていない（費用の判断が要るため）。数字は2026-10-16時点のCloudflareの公式文書による。変わりうるので、運営の前に確かめてほしい。

| 動かし方 | 手順 | 向く場面 |
|---|---|---|
| 手元のLAN | `npm run dev`。表示されたURLを大画面で開き、スマホは同じWi-Fiから読む | 試す、ボタン操作のゲーム |
| 手元のHTTPS | mkcert の証明書で `wrangler dev --local-protocol https`、またはcloudflaredのQuick Tunnel | 傾きを使うゲームの試験 |
| Cloudflareに置く | `npm run build` のあと `npm run deploy -w @irori/edge`（`wrangler login` が先に要る） | 公開、家族や学校で使う |

## 傾きのセンサーはHTTPSが要る

LANのURLをHTTPで開くと、スマホは傾きと画面の消灯防止を許さない。ボタンとスティックのゲームには影響しない。傾きのゲームを試すなら、Cloudflareに置くのが確実で、手元ならmkcertのルート証明書をiPhoneに入れ、「完全な信頼」をオンにする。Quick Tunnelは、WebSocketが通るか未確認。自己署名のHTTPSを押し切ったiPhoneがセンサーを許すかも、未確認。似た先行のOSS（HappyFunTimes）は、この点で行き詰まり、2020年に開発を終えた。

## 費用の上限は、プランで違う

- **無料プラン**：DurableObjectは、SQLite型だけが使える（既定のままで正しい）。1日あたり、リクエスト10万・実行時間1.3万GB秒・書き込み10万行。超えると、その種類の操作が止まり、**課金はされない**。UTC 0時（日本時間の朝9時）に戻る。
- **有料プラン**（月$5から）：超えた分はそのまま課金される。自動で止める上限は、公式文書に見当たらない。予算アラートは、通知だけで、止めない。
- **Workerを通さない静的ファイル**は、無料で無制限。このため、画面・ゲーム・SDKは静的に配り、Workerを通すのは、HTML・`/api`だけにしている。止まるのは、無料のときだけだ。

## 費用の見積もり（推測）

DurableObjectが受け取るメッセージは、20通で1リクエストと数える（課金の計算。送信は無料）。たとえば、4人が毎秒20通、ホストが毎秒10通を、20分続けると、受け取りは108,000通で、5,400リクエスト。無料枠にも同じ数え方が効くなら、1日に約18回遊べる。効かないなら、1回目の途中で枠が切れる。**実測はまだない。** 有料で月に1,000回遊ぶなら、約$0.66＋基本料$5。いちばん効くのは、入力の通数を減らすこと（スマホ側が毎秒20回までに間引く）。

## 自分で持つ栓

| 栓 | 既定 | 変える場所 |
|---|---|---|
| 同じIPの部屋の作成 | 毎分6・毎時60 | `LIMITS.CREATE_PER_IP` |
| 同じIPの接続の受け付け（部屋があってもなくても） | 毎分60 | `WS_CONNECT_PER_IP_PER_MINUTE`（`wrangler.jsonc`の`vars`。1〜10,000） |
| 同じIPの存在確認、存在しない部屋への接続 | 毎分30 | `LIMITS.LOOKUP_PER_IP` |
| IPv6 の数え方 | /64を1人、/48でも数える（上限は4倍） | `LIMITS.IPV6_48_FACTOR` |
| 1日（UTC）の部屋の総数 | 2,000 | `MAX_ROOMS_PER_DAY`（`wrangler.jsonc`の`vars`） |
| 1つの部屋の、待ち中の接続・新しい席・ロックの切り替え | 同時16・毎分40・毎分20 | `LIMITS.ROOM_*` |
| 部屋の人数・寿命 | 8人・無操作20分・最長12時間 | `LIMITS` |
| スマホ1台の送信 | 毎秒60・瞬間120 | `LIMITS.RATE` |

接続の受け付けは、再接続の波（家の8台が一斉に入り直す）が通る大きさにしてある。学校や会場のように、多くの端末が1つのIPアドレスの後ろにいるときは、この値を上げる。別のサイトのページから、訪問者のIPで部屋を作らせたり接続させたりする要求は、`Origin` を見て断る。curl や Node のクライアントは `Origin` を付けないので通る。

## 最悪の1日（推測）

無料プランは、枠を超えると止まるだけで、請求は来ない。有料プランには、自動で止める上限がない。栓が全部「上限いっぱいまで使われる」場合を天井に置くと、1部屋あたり約$0.24になる。8台が毎秒60通、ホストが毎秒40通を12時間続けると、受け取りは2,246万通で、112万リクエスト（約$0.17）。実行時間は128MBで5,530GB秒（約$0.07）。`MAX_ROOMS_PER_DAY` が既定の2,000なら、部屋だけで1日約$475になる。

席の作成とロックの保存は、1回で1行の書き込みで、攻撃者のIPアドレスの数に比例して増える。1アドレスあたり、1日に最大およそ17万行（約$0.17）。実際の攻撃はこれより小さいはずだが、設定の根拠には、この天井を使う。

有料なら、払える1日の最大額を$0.24で割った値を `MAX_ROOMS_PER_DAY` にし（$25なら100）、予算アラートも入れる。アラートは通知だけで止めない。見張るのは自分だ。無料なら、15前後に下げる（上の見積もりの目安）。

## 運用の注意

- **デプロイすると、すべての接続が一度切れる。** 部屋と席は保存されるので、スマホは自動で入り直す。遊んでいる最中は避ける。
- **ログと個人情報。** 既定では、Workers Logsを有効にしていない。IPは保存せず、日ごとに変わる塩つきのハッシュだけを数える。名前は部屋と一緒に消える。Cookieも外部への送信もない。運営者が解析や広告を足すときは、利用者への通知・公表など、法令上の手続きが要る（[legal/](legal/)）。
- **止まったとき。** 日次の上限や無料枠で止まると、ホストの画面に理由と、あとで試すまでの目安が出る。手元のLANで遊べる案内も添える。
- **ホストの環境。** 正式に対応するのは、PCのブラウザ（Chrome・Safari・Edge・Firefoxの最新版）。TVの内蔵ブラウザとタブキャストは、動けば可。
- **外部のゲームを載せる運営者へ。** 審査は完全ではない。権利者からの申立てや、問題の報告を受ける窓口と、取り下げの手順を決めておく（[registry.md](registry.md)）。
