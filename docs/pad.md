# コントローラーの画面は、定型6種から選ぶ。自由なHTMLは持ち込めない

ゲームは `setPad` で、スマホに出す画面の種類と中身（ボタンの文字など）を指定する。スマホ側の描画と入力の取り方は、コンソールが引き受ける。型は [`types.ts`](../packages/protocol/src/types.ts) の `GamePadSpec`。

## 6種の使い分け

| 種類 | 向くゲーム | 届く入力 | 気をつけること |
|---|---|---|---|
| `wait` | 待ち時間・説明・結果の表示 | なし | 文字だけ。何を待っているかを1行で書く |
| `pad` | 移動して行動する | `btn` `axis` | 十字キーかスティックに、ボタンを最大4つ。横向きが要るなら `orient` で案内する |
| `buzzer` | 早押し・連打 | `btn` | 大きなボタン1つ。押した瞬間に反応し、離すまで再発火しない |
| `choices` | 選択式・多数決 | `pick` | 2〜6個、文字は12文字まで。答えたら `disabled` にして二重回答を防ぐ |
| `touch` | なぞる・スワイプ | `ptr` | 座標は枠の内側を0〜1にした値。枠の外の指は終端として扱う |
| `tilt` | 傾けて操作する | `tilt` `btn` | iOSは初回に許可が要る。HTTPSでないと動かない（家のLANのHTTPでは使えない） |

選び方の目安は、人数が多いほど入力を単純にすること。8人で `axis` を毎秒20回送ると、ホストへ毎秒160通が届く。回線にも費用にも効く。

## 共通の約束

- 文字数の上限は、ボタンの文字12・ヒント40・見出し24・本文120（符号位置の数。日本語は1文字が1つ）。色は `red` `blue` `green` `yellow` `gray` の名前だけ。任意のCSSは流し込めない。
- 画面は何度でも差し替えられる。差し替えの瞬間に、押しっぱなしのボタンは離したものとして扱い、`btn` の `d:0` を補う。ゲームは「離し忘れ」を考えなくてよい。
- スティック（`axis`）とタッチ（`ptr`）は、押している間、値が変わらなくても約1秒ごとに同じ値が届く。3秒来なかったら、その席の入力を中立に戻してよい（離した知らせが届かないまま接続が死んでも、ゲームが暴走しないため）。ボタン（`btn`）は押した・離したの2回だけ。席が切れたら（`players` の `online`）、ゲームが入力を中立に戻す。
- 再接続したスマホには、直前の画面が自動で戻る。ホスト側のSDKが覚えていて再送するので、ゲームは何もしない。
- 席の色と形は、スマホの縁に常に出る。ゲームからは変えられない。左上の長押しで開くメニュー（一時停止の依頼・退出）も、ゲームは奪えない。
- 描くときは、文字をすべて `textContent` で入れ、HTMLとして解釈しない。

## 作らないもの

- **自由なHTMLのコントローラー**：スマホ側でも第三者のコードが動くことになる。許可・再接続・画面の消灯・読み上げを、ゲームごとに作り直させたくない。6種で表せない実例が3件集まったら考える。
- **文字入力**：内容の検査が要る。名前だけは参加時に受け付ける。
- **画像・アイコンの送信**：帯域と、不適切な画像・他人の権利物が紛れ込む心配がある。
- **スマホからの音の再生**：音の主役はホストの大画面。スマホからは振動（`fx`）だけを送れる。iOSのSafariには振動がないので、あっても無くても遊べる作りにする。
- **カメラ・マイク・位置情報**：要求しない。ゲームが `allow` で要求しても、枠の権限で拒否する。

## 試験のやり方

見た目のスナップショットではなく、実ブラウザで「押す・離す・なぞる → 想定のフレームが出る」を種類ごとに確かめる。押しっぱなしの途中で画面を差し替える試験と、再接続後に画面が戻る試験を、必ず入れる。この2つが、実機で最初に壊れる。
