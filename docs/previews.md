# 棚で流すゲームの動画

ゲーム自身の大画面だけを録画する。外部素材・字幕・音・生成した映像は混ぜない。
全13本を `registry/previews/<id>.mp4` に置き、CC BY 4.0 として扱う。

## 再生成

メインが確認用サーバーと撮影用ブラウザを起動してから実行する。
道具はサーバーを起動・停止せず、専用のブラウザ文脈だけ作って閉じる。

撮るときは、書体のファイル（Noto Sans JP・SIL OFL）の場所を `IRORI_FONT_JP` で渡す（取得先と SHA-256 は `tools/lib/ofl-fonts.mjs` の冒頭。ファイルはリポジトリに入れない）。
```sh
IRORI_FONT_JP=<Noto Sans JP のファイル> nice -n 10 node tools/make-previews.mjs
IRORI_FONT_JP=<同上> nice -n 10 node tools/make-previews.mjs --base-url http://127.0.0.1:8787 --only old-maid
nice -n 10 node tools/make-previews.mjs --verify-only   # 検査だけ。書体は要らない
```

接続先は `ws://127.0.0.1:9333/pw`。録画は1280×720のページ全体。
`?mock=N` の人数は台本で指定し、仮想パッドの帯はCSSで隠す。
台本の `query` で `demo=1` などの撮影元を選べる。未指定なら従来の `mock=N`。
文字は、OS の書体（Hiragino や SF）でなく、再配布してよい Noto Sans JP に差し替えて撮る。動画を CC BY 4.0 で配るため（`docs/legal/rights-check.md`）。
差し替えは、ページの CSS と canvas の書体の指定の両方に行い、撮る前に、画面に OS の書体の文字が残っていないことを確かめる（残っていれば動画を作らずに止まる。見えない仮想プレイヤーの帯は除く）。
書体のファイルが無い・確認ずみのものと違うときも、ブラウザにつなぐ前に止まる。
`ffmpeg` と `ffprobe` は既定の導入先を使う。別の環境では
`IRORI_FFMPEG` と `IRORI_FFPROBE` で実行ファイルを指定する。

## 操作の方針と落とし穴

- 有効なボタン・選択肢・札・タッチ面をDOMから選ぶ。操作の乱数の種は固定。
- ゲームの内部モデルや秘密の情報は参照せず、時計や勝負の結果も変更しない。
- ゲーム本体の配札は毎回変わりうるので、動画のバイト一致は保証しない。
- `tools/preview-scripts/<id>.mjs` は人数・撮影元・操作設定・書き出し秒数、必要なら操作関数を上書きできる。
- 棒を倒す操作は押したまま方向を変える。瞬時に離すと、移動を見せられない。
- 台本の `capture` は残す区間を秒で返せる。実際の操作順を保ち、静止区間だけを省く。
- 灯市は約30秒撮影し、同じ対戦内の連続した9〜10秒だけを選ぶ。途中を切ったり別対戦へつないだりしない。
- 札選択は各席0.2〜0.5秒、公開後の進行は0.4〜0.8秒。途中は無編集。端を重ねる場合も両端の0.4秒だけにする。
- 一斉公開が2回以上入り、得点が時系列どおりであることを9コマでも確認する。
- 「おわる」は自動で押さない。静止の多いゲームは、撮影区間と操作間隔を調整する。
- 10秒を数える遊びは3人が9.5〜10.5秒で押す。実時間で3回計り、数え始めと結果を残して静止区間を省く。

## 新作2本の撮り直し

2本は仕上げ途中の暫定動画。ゲームの変更後はサーバーを起動し直して撮る。

```sh
nice -n 10 timeout 3000 env IRORI_DEV_PORT=8834 node tools/dev.mjs
# 別の端末で、1本ずつ実行する
nice -n 10 node tools/make-previews.mjs --base-url http://127.0.0.1:8834 --only bell-in-sleeve
nice -n 10 node tools/make-previews.mjs --base-url http://127.0.0.1:8834 --only poker
```

- 鈴は6席の `mock=6`。全種類が配られる人数を使い、未撮影の効果を有効な札から優先する。
- 各効果の初回操作から1.6秒を時系列で残し、最後に結果2.5秒。必要な効果が出ない局は採用しない。
- ポーカーは4席の `mock=4`。最初に1回ふやし、その後はあわせる・そのままで手札公開まで進める。
- 同じハンドの配札から勝者まで連続した10秒を残す。途中は切らず、手札公開と勝者を読む間を残す。
- 両方ともCPU観戦より入力待ちが短く、10秒前後で見せ場がそろうため仮想パッドを選んだ。
- 操作の種は20261106。配札の乱数は変更しないため、同じ手札・勝者・動画のバイト一致は保証しない。
- 撮影後は9コマ画像と継ぎ目を確認し、サーバーを止める。検証記録は担当報告へ残す。

## 書き出しと確認

原則10秒（台本指定で8〜12秒）・640×360・30fps・H.264・yuv420p・無音・faststartで書き出す。
末尾0.5秒を先頭の0.5秒へ重ね、ループ後はその直後から続く。
候補は `.probe-tmp/previews/<id>.mp4` に出し、全機械検査に通ってから正式なMP4へ置き換える。
既存の正式ファイルは、置換前に必ず `.probe-tmp/previews/_backup/<id>-<時刻>.mp4` へコピーする。
検査か退避に失敗したときは正式ファイルを変えない。目視不合格時は退避から戻せる。

道具は容量1,000,000バイト以下、長さ8〜12秒、映像形式、音声の流れが無いことを検査する。
先頭と3コマ後の輝度差を比べ、32画素以上が変化し平均差0.01以上であることも確かめる。
さらに0.5秒ごとの代表コマを比較し、同じ画素差の条件を満たす区間の割合（活動率）が0.6以上か確かめる。
基準用4本の活動率は0.632〜1.000。圧縮雑音や先頭だけの動きでは合格させない。
これは動きの最低限の検査で、見せ場の良さや文字の読める大きさは保証しない。
`.probe-tmp/sheets/<id>.png` の9コマを開き、空白・黒画面・文字の欠けを目で確かめる。
元の録画と編集候補は `.probe-tmp/previews/`。公開物に混ぜない。

```sh
nice -n 10 node --test tools/tests/make-previews.test.mjs
nice -n 10 npm run check
nice -n 10 node tools/check-budgets.mjs
```

検査だけでは、実機での自動再生・人が見たときの自然さ・公開先での配信は確かめられない。
