# 棚に並べるのは登録情報だけ。ゲーム本体は制作者が持つ

ゲームをアップロードする窓口は作らない。保管・審査・通報・個人情報・規約の運用を、保守者1人で引き受けられないため（[ADR 0003](decisions/0003-registry-by-pull-request.md)）。代わりに、登録情報のJSONをPRで足してもらう。ゲーム本体は、制作者が自分で配信するか、このリポジトリの `games/` に置く。

## 登録の流れ

1. [sdk.md](sdk.md) に沿ってゲームを作る。
2. `registry/games/<id>.json` と、サムネイル `registry/thumbs/<id>.png`（または `.webp`。640×480、120KB以下）を足してPRを出す。形は [`game.schema.json`](../registry/schema/game.schema.json)。`<id>` は英小文字・数字・ハイフン。
3. CIが機械で確かめる。通らなければ、理由がPRに出る。
4. 保守者が内容を読んで、下の基準で採否を決める。採らないときは、理由と、直せば通る点を返す。
5. 取り込まれたら、次のデプロイで棚に並ぶ。

## CIが確かめること

- スキーマに合うこと。`id` がファイル名と一致し、`added` が未来の日付でないこと。
- サムネイルが指定の大きさと形式で、容量内であること。外部の画像は読み込まない。
- `entry.bundled` なら、そのフォルダに `index.html` があること。`entry.url` なら、https で応答し、ヘッドレスブラウザの隔離した枠に読み込んで10秒以内に握手と `ready` が届くこと。
- ライセンスの表記が、許可した一覧（よく使うSPDXの識別子と `LicenseRef-closed`。`original` は素材だけに使える）にあること。
- 同梱のゲームは、`irori.js` がSDKの最新のビルドと一致していること。

## 人が見ること

機械では判断できないので、保守者が読む。基準は6つ。

| 基準 | 見るポイント |
|---|---|
| 全年齢 | 暴力・性的表現・賭博性・差別がなく、子どもが同席しても困らない |
| 権利 | 自作か、許諾を得た素材だけ。他社のキャラクター・商標・音楽・画像、他のゲーム機やサービスの見た目の模倣がない |
| 通信 | 外へ何を送るかの説明がある。個人情報の収集、解析、広告、課金への誘導がない |
| 遊べる | 起動して、終わりまで遊べる。`end` に至る道がある。人数の宣言が正しい |
| 入力 | スマホの画面が [pad.md](pad.md) の範囲で、人数に見合った入力量である |
| 名前 | 既存のサービス・商標と紛らわしくない |

登録は、保守者が内容を保証するものではない。審査は完全ではなく、外部のゲームは取り込み後に変わりうる。

## 取り下げ

権利者からの申立て、安全上の問題、長期の不具合があれば、保守者がJSONを削除する。申立ては [SECURITY.md](../SECURITY.md) の窓口（非公開）で受け、確認ののち、目安として7日以内に対応する。外部ゲームの定期的な握手の検査（月に1回など）は、まだ作っていない（未実装）。いまは、利用者や権利者からの報告で確かめ、動かないものは保守者が棚から外す。

## 参加しやすい作業

- サムネイルや説明文の英訳を足す（コードに触れなくてよい）。
- `games/hello-pad` を改造して、最初のゲームを登録する。
- 登録済みのゲームを遊んで、人数や入力の宣言が合っているか報告する。
