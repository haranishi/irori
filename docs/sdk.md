# ゲームは、ホストの画面で動く普通のWebページとして作る

ゲームは大画面のブラウザの中、隔離した枠（iframe）で動く。スマホからの入力はイベントで届き、ゲームの状態はゲームが自分で持つ。通信、部屋、スマホの画面、再接続は、SDK（[`packages/sdk`](../packages/sdk)）の向こうにあるコンソールが引き受ける。SDKは1ファイルで、依存がない。ゲームのフォルダに写して使う。

```html
<!-- index.html -->
<canvas id="c" width="960" height="540"></canvas>
<script type="module" src="./main.js"></script>
```

```js
// main.js
import { connect } from './irori.js';
const irori = await connect();
const ctx = document.getElementById('c').getContext('2d');
const pos = new Map(); // 席番号 → 位置

irori.setPad({ k: 'pad', stick: 'stick', buttons: [{ id: 'jump', label: 'ジャンプ' }] });
irori.on('input', (p, i) => {
  if (i.k === 'axis') pos.set(p, { x: i.x, y: i.y });
});
irori.ready();
// 描画ループは通常のゲームと同じ。席の色は irori.look(席番号) で取る。
```

## 呼び出し

| 呼び出し | 役割 |
|---|---|
| `connect(options?)` | 握手して `irori` を返す。ホストの外で単体で開いたときは、開発用の仮想プレイヤーに切り替わる |
| `irori.players` / `irori.leader` | 席の一覧（番号・名前・接続中か）と、リーダーの席番号 |
| `irori.capabilities` / `irori.environment` | ホストが持つ追加機能と、接続・表示の最新状態。古いホストでは `[]` / `null` |
| `irori.on(name, fn)` | `players` `input` `pause` `resume` `environment` を購読する。戻り値で解除 |
| `irori.setPad(spec, to?)` | コントローラーの画面を指定する。`to` は席番号か `'all'`（既定）。種類は [pad.md](pad.md) |
| `irori.vibrate(ms[], to?)` | 振動を頼む。届かない端末もある |
| `irori.cue(name, v?)` | コンソールに合成音を頼む。強さ0〜1（既定0.7）。`cue-v1` が無ければ何もしない |
| `irori.look(id)` | 席の色と形。ゲームの中の表示を、コンソールとそろえるために使う |
| `irori.ready()` | 最初の画面が出せたら呼ぶ。10秒以内に呼ばないと、コンソールが中断を勧める |
| `irori.end(results?, options?)` | 終わりを知らせる。結果画面と「もう一度」はコンソールが出す。呼んだあとの `setPad` と `vibrate` は、コンソールのリモコンを上書きしないよう無視される |
| `irori.storage.get/set` | ゲーム専用の小さな保存。1つ16KB、合計64KBまで |

## 記録の表示と環境の通知

結果は `{ p, score, label?, ranked? }` を最大8行。`ranked: false` は記録だけを残し、順位・優勝の対象から外す。
`options` は `display: 'points' | 'record'`、`outcome: 'complete' | 'incomplete'`、120文字以内の `note`。
`record` は全行の `label` を必須とし、点数の代わりにその文字を表示する。`incomplete` は全員順位なし。
省略時は従来の点数表示・通常終了になる。ラベルは12文字以内。追加フィールドを使う前に `result-options-v1` を確認する。
対応しないホストへ拡張した結果を送ると `unsupported-feature`。省略した旧形式の結果はそのまま使える。

`host-environment-v1` があると、`environment` で `{ connected, visible }` を読み、同名イベントで変化を購読できる。
メニューの `pause` / `resume` とは別の状態。接続や表示が戻っただけで、計測を自動再開しないようにする。
経過時間は同じ画面の `performance.now()` 同士で測る。入力の `T` と引き算しない。通信の遅れは記録に含まれる。

## 作るときの決まり

- **一時停止を守る。** `pause` が来たら、タイマーとアニメーションを止める。コンソールのメニューが前面に出ている。
- **途中参加は次のゲームから。** ゲーム中に入った人は、待機画面になり、そのゲームの `players` には現れない。`players` は、ゲームを始めたときの席から、`online` の変化と、席が空いたこと（猶予の60秒切れ・退出・外された）だけが届く。空いた席に別の人が入っても、その人は参加者にならない。
- **席が切れたら、待つのを基本にする。** `online` が偽の席は「いま操作できない」だけで、まだ参加者。猶予の60秒が過ぎて `players` から席が消えるまでは、点や回数を保ち、戻れば続きから遊べるようにする（スマホの切断画面が「つながったら、そのまま続けられます」と約束しているため）。棄権や不在の扱いは、席が消えたときだけにする。待つか、外すか、AIに任せるかはゲームの設計で、SDKは決めない。同梱ゲームは、この形にそろえてある。
- **結果には、途中で席が消えた人も載せる。** `end(results)` には、始めたときの参加者の全員を、そのときの点や回数のまま入れる。名前はコンソールが控えていて、抜けた人の行に「退出」の印を付けるので、ゲームは名前を持たなくてよい。同梱ゲームは、この形にそろえてある。
- **`end` を呼ぶ道をすべて作る。** 勝ち・時間切れ・全員退出・やり直し。「はじめる」の前に全員が席を立つ道も含める。終わり方が複数あるゲームは、全部の道を最後まで試験する。
- **`end` の直前に送った画面は、スマホに届かないことがある。** `end` を呼ぶとコンソールは枠を閉じ、スマホを結果のリモコンに差し替える。最後に見せたい画面（人狼の全員の役の公開など）があるなら、`end` を数秒遅らせる（同梱の人狼は8秒置く）。
- **スクリプトは別のファイルに置く。** 同梱のゲームには、インラインの `<script>` を動かさないCSPがかかる（`<style>` は動く）。
- **データは `import` で読む。** 同梱のゲームの枠は、オリジンが空なので、Safari（WebKit）では、自分のファイルへの `fetch` がCSPの `connect-src 'self'` で止まる（実測）。JSONは `export default` のJSモジュールにして `import` する。Chromium では `fetch` も通るので、試すときに気づきにくい。
- **ホストの画面を再読み込みすると、ゲームは結果なしで終わる。** 部屋と席は残り、ホームに戻る。続きから遊ばせたいなら、`storage` に状態を書く。
- **枠の外へ出ようとしない。** ポップアップ、`alert`、画面遷移、フォーム送信、Cookie、`localStorage` は使えない。保存は `storage` を使う。
- **スティックの入力は見張る。** `axis` と `ptr` は、押している間、約1秒ごとに届く。3秒来なければ、その席の入力を中立に戻す。席が切れたとき（`players` の `online` が偽）も同じ。ボタンは押した・離したの2回だけ届く。
- **色だけで区別しない。** 席は `look` の色と形の両方で描く。赤と緑で意味を分けない。
- **早押しの順番は `T` で見る。** 入力に付くサーバーの受信時刻で、ホストに届いた順より安定する。ただし回線の遅れは公平にできない。
- **音はコンソールが鳴らす。** `irori.cue` は消音・最初の操作の前・ゲームが前面でない間は捨てる。同じ名前は50ms間隔、全体は直近1秒に20件まで。仮想プレイヤーは無音。ゲーム側で音声ファイルを読み込む必要はない。
- **重くしない。** ホストはノートPCやTVのブラウザかもしれない。60fpsを保てない端末では、描画を間引く道を用意する。

## 動かしながら作る

1. **仮想プレイヤー**：ゲームを単体で開き、`?mock=3` を付ける。キーボード（1人目はWASD、2人目は矢印）と画面脇の小さなパッドで、3人分を1台で操作できる。通信は要らない。
2. **本物のスマホで**：`npm run dev` でコンソールを起動し、LANのURLを大画面で開く。ゲームを別のポートで動かし、`/?dev=http://…` で読み込む。`dev` はローカルとLANの上のコンソールでだけ有効で、公開サーバーでは無視する。同梱の `games/` や登録情報を直したときは、`npm run prepare:web` で配る場所へ作り直す（`npm run dev` は、起動のときに1回だけ作る）。

## 棚に並べる

[registry.md](registry.md) に従い、登録情報のJSONを1つ足してPRを出す。ゲーム本体は自分で配信するか、このリポジトリの `games/` に置く。

## 外部のゲームへの約束

外部のURLのゲームは、自分のオリジンで動き、そのサーバーに通信できる。コンソールは、開く前にホスト名を表示して知らせる。通信の内容は、コンソールからは制御しない。登録の審査では、ゲームが何を外へ送るかの説明を求める。

枠を開いてから握手までは、同梱のゲームが3秒、外部のゲームが10秒まで待つ（遠いサーバーから読むため）。握手のあと10秒以内に `ready` が来ないと、中断を勧める。


## 札の選択と旧ホスト

`irori.capabilities.includes('pad-tiles-v1')` を先に確認する。能力がなければ `irori.setPad({k:'wait',title:'更新が必要です'})` で待つ。
能力なしの `setPad({k:'tiles',…})` は送信前に `IroriError('unsupported-feature')`。対応時は [pad.md](pad.md#tiles-の指定と操作) の指定を使い、`input.k === 'tiles'` の `ids` と `pass` を読む。`token` を指定したら、入力の `t` が現在の値と一致するものだけを受け付ける。
仮想プレイヤーの札は席をクリックしてから、矢印で移動・Spaceで選択・Enterで決定・Pでパス。クリックとも併用できる。

## 合成音の名前

`tick` `confirm` `deny` `turn` `win` `lose` `count` `go`、札の `deal` `flip` `place` `sweep` `revolution`、
投球の `roll` `pins` `strike` `spare` `gutter`、村の `night` `dawn` `vote` `execute` `reveal`。
`v` は0〜1に丸め、`pins` では強さに加えて長さと粒の数も変わる。聞こえ方は人の耳での確認がまだ必要。
