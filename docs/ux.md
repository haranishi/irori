# 入って15秒で遊べることを、設計の基準にする

基準は一つ。最初のグループが、ホストの画面を開いてから最初のゲームが始まるまでを、説明もインストールもアカウントも要らずに終えられること。スマホ側は、QRを読んで「参加する」を1回押すだけにする。画面と操作の数は、この基準から決めた。実装の前に書き、実装が変わった箇所は末尾に記録している。見た目の決まりは [identity.md](identity.md) へ。

## ユーザーストーリー

本命は「ホストになる人」と「参加する友だち」。救いたい相手は、コントローラーを持っていない人、アカウントを作れない・作りたくない子どもや年配の家族、ゲームは作れるが通信の実装で止まる制作者。

| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| ホスト | URLを開くだけで遊べる状態になってほしい。準備で友だちを待たせたくない | インストールもログインもなしで、最初の画面にQRと4文字のコードが出る |
| ホスト | 人数に合うゲームだけを選びたい。足りないゲームで始めて白けたくない | カードに必要人数が出る。いまの人数で遊べないものは灰色になり、理由が1行出る |
| ホスト | 座ったまま、スマホで選びたい。PCまで立ちたくない | 最初に入った人のスマホが、十字キー・決定・戻るのリモコンになる。キーボードとゲームパッドでも同じ操作ができる |
| ホスト | 誰かの回線が切れても、ゲームを止めずに戻したい | 切れた人は一覧に「つながっていません」と出る。60秒以内に同じブラウザで開き直せば同じ席に戻る |
| 友だち | アプリを入れず、名前も打たず、1タップで入りたい | QRを読み「参加する」を押すだけで入れる。名前は任意で、空なら「プレイヤー3」になる |
| 友だち | 自分がどれか、ひと目で分かりたい | 色と形（●■▲◆…）が、スマホの縁とホストの一覧に出る。色だけに頼らない |
| 友だち | 画面が消えても、戻ったら続きから遊びたい | 対応端末では画面を消さない。閉じても同じURLで席に戻る |
| 遅れて来た友だち | 途中からでも入りたい。ただし邪魔はしたくない | ゲーム中は「次のゲームから参加できます」と待機画面が出る。ホームに戻れば遊べる |
| 制作者 | 通信もスマホ画面も作らず、ゲームだけ作りたい | SDKの小さなAPIで入力が届く。ホストなしでも、キーボードの仮想プレイヤーで動かせる |
| 制作者 | 作ったゲームを、PR1本で棚に並べたい | 登録情報のJSONを1つ足す。CIが形と動作を検査して結果を返す |
| 運営者 | 費用が膨らまないでほしい | 部屋・接続・メッセージ・1日の部屋数に上限があり、超えたら画面に理由が出る |
| 運営者 | 変なゲームが混ざっても被害を広げたくない | ゲームは隔離した枠で動き、ホストの画面と通信路に触れない |

## UX5階層

| 階層 | 決めたこと |
|---|---|
| ①戦略 | 1台の画面を囲む遊びを、アカウントもインストールもなしで、誰でもゲームを足せる形で開く。差別化の源泉は3つ。ゲームの追加がPR1本で済むこと、上限つきで自分で運営できること、通信とスマホ画面の部品を制作者が作らずに済むこと |
| ②要件 | 載せる：ホーム（棚・QR・参加者）、コントローラー7種、結果、メニュー、共有、再接続、キーボードとゲームパッドの操作、開発用の仮想プレイヤー。載せない：アカウント、チャット、ランキングの保存、課金、広告、解析、ゲームのアップロード、文字入力 |
| ③構造 | ホーム → ゲーム → 結果 → ホーム。ロビーは別画面にしない。迷う分岐と復帰路は、人数不足→灰色と理由／リーダー不在→次の席へ自動で移る／回線切れ→席を60秒残す／満員・ロック→理由を出す／ホスト切断→スマホに「ホストを待っています」 |
| ④骨格 | ホストの主役は、選択中のゲームのカード1枚。QRとコードは常に右下。参加者は下の帯。3m離れて読める大きさ（1080pで本文24px以上）。スマホは、親指が届く下半分に操作、上に状態と自分の色。ボタンは48px以上 |
| ⑤表層 | 囲炉裏の暖かい暗色の地に、残り火の橙。プレイヤー色は色覚に配慮した8色に形を足す。動きは控えめ（reduced-motionを尊重）。音は合成した短い音だけ |

## 通したことで変わった実装（12か所）

5階層を通す前は、次のように作るつもりだった。

1. ロビーを別画面にする → ホームに統合した。いつでも参加でき、カードが人数を見て灰色になる
2. スマホで4文字のコードを打たせる → QRのURLの `#` 以降にコードを入れる。打つ入口は、コードがないときだけ出す
3. ホストはマウス操作 → キーボード・ゲームパッド・リーダーのスマホで同じ操作にし、フォーカスの輪を大きくした
4. リーダーという考えがなかった → 最初に入った人のスマホをリモコンにする。抜けたら次の席へ移る
5. 名前だけで区別する → 色と形を席番号から決め、スマホの縁とホストの一覧に出す
6. ゲームが終わったらホームへ戻す → 結果（順位・もう一度・ホームへ・共有）を挟み、「もう一度」を最初の選択にする
7. 切断は黙って自動再接続 → スマホに帯で出し、ホストの一覧にも「つながっていません」と出す
8. 遅れて来た人は想定外だった → ゲーム中は待機画面、ホームでは入れる
9. スマホにメニューがなかった → 左上の長押しで「一時停止の依頼・退出」。誤タップを避けて長押しにした
10. 共有は想定外だった → ホームと結果に、Xとラインと共有シートとリンクのコピーを置く
11. 画面の消灯と向きは想定外だった → Wake Lockを使い、横向きが要るゲームでは向きの案内を出す（iOSは向きを固定できない）
12. 初回の案内は想定外だった → 最初の1人が入るまで、3手順（QRを読む→参加する→ゲームを選ぶ）を出す

## 保留にしたもの

- **文字入力（名前以外）**：内容の検査と不適切な文字列の扱いが要る。2本以上のゲームで必要になったら考える。
- **自由なコントローラーHTML**：スマホ側でも第三者のコードが動き、許可・再接続・読み上げを各ゲームが背負う。定型7種で表せない実例が3件集まったら再検討する。
- **観戦・配信・録画**：ホストの画面をそのまま映せば足りる。専用の機能は作らない。
