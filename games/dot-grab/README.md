# あつめて点：時間差 dt で動かし、届かなくなった入力で暴走させない見本

45秒のあいだ、スティックで動いて光る点を集める。点は一度に8個まで出ていて、取られると0.7秒後に、なるべく誰からも離れた場所へ出直す。得点は取った数で、終わり方は2つ（時間切れ・全員退出）。logic.test.js が、どちらも end まで通している。切断（`online` が偽）は「いま動かせない」だけなので、その場で止めて点を保ち、戻れば続きから動ける。全員が切れても終わらず、席が全部消えたときだけ「全員退出」で終わる。

## 使っているSDKの機能

スティックだけの `pad` を出す `setPad`、`on('input')` で届く `axis`、点を取った人だけへの短い `vibrate`、`pause` と `resume`。

## 速さは、フレーム数でなく dt で決める

動きは、前のフレームからの秒数 dt を掛けて進める。20fps の端末でも144fps の端末でも、1秒で進む距離は同じになる（試験で確かめている）。止まっていたタブが戻ったときの大きな dt は0.1秒に抑えて、壁を突き抜けないようにした。点との当たりは、そのフレームで動いた線分で見る。速く動いても点をすり抜けない。

## 最後のスティックの入力から3秒で止める

ここがこの見本でいちばん大事な落とし穴だ。離した知らせ（0,0）が届かないまま回線が切れると、最後の向きのまま走り続けてしまう。スマホの画面は、スティックを倒している間、値が変わらなくても約1秒ごとに同じ値を送り直す（[docs/pad.md](../../docs/pad.md)）。そこで、最後の `axis` から3秒たったら止める。席が切れた（`online` が偽になった）ときは、その場ですぐ止める。

十字キー（`dpad`）の入力は、値が飛び飛びで送り直しが起きない。使うなら、3秒を延ばすか、押し直す遊び方にする。

## 改造するときに気をつけること

- 時間・速さ・点の数・止めるまでの時間は、logic.js の先頭の定数にまとめてある
- 60fpsを保てない端末では、描画を1フレームおきにしている（main.js の `slow` と `skip`）。動きと時計は毎フレーム進める
- 一時停止のあいだも `axis` は受ける。離した知らせを捨てると、再開した瞬間に走り出すため
